## 一、版本号规则（2026-10-09 与用户商定）

版本号形如 **`A.B.C.D`**：

| 位 | 含义 | 规则 |
| --- | --- | --- |
| **A** | 平台 | 现在 **0**；**等有安卓端联动再升 1** |
| **B** | 底层架构世代 | **2** = 从 Python 改成现在这套 C#/.NET 架构的那一代（`v0.1` 是 Python 版，`v0.2` 是这一代） |
| **C** | 推出的版本 | 每推出一个正式版本 +1（用户拿到、能装、能用的版本） |
| **D** | 测试版序号 | 给**某一版**做完善/优化的测试版：`.1`、`.2`…… `.5` 表示"C 版打包完成之后的基本优化版" |

当前：**`0.2.1.5`** = 第 0 代平台、C# 世代、第 1 个正式版（0.2.1）打包完成之后的测试版。

> 旧叫法对照：老文档里的 `v2.0.0` / `v2.0.1` 就是新规则的 **`0.2.0` / `0.2.1`**（第二位那个 2 也是"架构世代"的意思，只是位置换了）。

## 二、目录与流程约定

| 约定 | 说明 |
| --- | --- |
| **正式版**（C 位 +1，例如 `0.2.1`、`0.2.2`） | 才**打安装包**、才更新 `newest\`、才做 `历史版本\v<版本>-存档-<日期>\` 存档 |
| **测试版**（D 位，例如 `0.2.1.5`） | **不打安装包、不动 `newest`**；只在 `v0.2\v<版本>\` 里留一份快照（素材 + 源码快照 + 说明） |

**教训（我自己造成的，记下来免得再犯）**：
- 我用"读文件 → 全量字符串替换 → 写回"的方式批量改路径，结果把一个文件里的 `v` 替换成了 `0`（`private`→`pri0ate`）、
  把 `@{` 替换成了 `{{`，**弄坏了 3 个 .cs 和 2 个 .ps1**，编译立刻报一堆 `const` 位置错误。
  ⇒ 批量替换**必须**：① 先用 `[regex]::Matches(...).Count` 断言**只匹配 1 次**再替换；② 改完**立刻编译/跑自检**；
  ③ 代码文件优先用单点编辑，不用全量替换；④ 有快照就从快照恢复（这次就是靠 `v0.2.1.5\源码快照\` 救回来的）。
- `edit`/`write` 保存 `.ps1` 时会**丢掉 BOM** → PS 5.1 按 GBK 读中文脚本直接语法错误（已经犯两次）。

**教训（第二十一轮：设置里连点勾选丢勾）**

- **现象**：快速连点几个勾选框，只有**最后一次**生效；第一次点击的弹窗（提示）是真的，但结果被下一次点击覆盖。
- **根因**：**列表快照 + 整体替换**。建面板时 `var current = _settings.StatsViews;` 缓存了**引用**，而回调里 `_settings.StatsViews = ordered;` 把设置换成了**新列表** → 第二次点击仍从**旧列表**算起，前一次被覆盖。
- **规则**：凡是"多选/多值"控件，回调里**必须实时读取当前值**（`var live = _settings.X;`），**绝不能用建面板时的快照**；单值（bool/数字/字符串）每次写绝对值，没这个问题。
- **同类排查**：`ListEditor`（种类/支付方式）安全 —— 它持有一份自己的副本，回调给的是**完整最新状态**。

**教训（图表：先查权威实现，别一轮轮猜）**

- 3D 饼图来回改了 7 轮都没让用户满意，最后**读 `plotrix::pie3D` 源码**（[pie3D.R](https://sources.debian.org/src/r-cran-plotrix/3.8-2-1/R/pie3D.R/)）才发现它是纯 2D 多边形、参数是 `2θ/π` 压扁 + `explode` 沿对称轴外移 + `shade` 平涂 + 白边，按它移植一次就对了。**有成熟实现时先读源码，比自己调参快得多**。
- "上下溢出个蓝点"这类"看起来玄学"的问题，多半是**几何尺寸算错**（画布比图形矮 13px，而 WPF `Canvas` 默认不裁剪）→ 算准尺寸 + `ClipToBounds`。
- 真要"真 3D"：WPF 自带 `Viewport3D`/`Media3D` **在 PresentationCore/PresentationFramework 里，给安装包加 0 字节**；会加体积的是第三方库（SkiaSharp native 包曾涨 5 倍、HelixToolkit 是额外依赖）。


**教训（PowerShell 变量名大小写不敏感）**：写文档脚本时用 `$h` 存路径、又用 `$H` 存行数组 —— PowerShell 里 **`$h` 与 `$H` 是同一个变量**，路径被覆盖成数组 → `WriteAllText` 报"路径中具有非法字符"。**同一段脚本里给路径和内容起名要拉开距离**（如 `$handPath` / `$handLines`）。

**教训（2026-10-13：重建运行目录把用户数据删了）**

- **现象**：`工具\出测试版运行目录.ps1` 里是 `Remove-Item $run -Recurse -Force` 再重建 → 把用户在 `v<版本>\运行\` 里"双击就能跑"期间**记的账**一起删了（`Remove-Item` 不进回收站，删了回不来）。
- **修法**：重建前先把 `数据/配置/导出/备份/日志` 挪到 `临时\保留-<时间戳>\`，重建后再放回（已实测：放个假账本进去重建，内容原样还在）。
- **规矩**：凡是"用户可能在里面产生数据"的目录，脚本**绝不允许**直接整目录删除；要删只能删程序文件那一层。

**教训（2026-10-13：批量改代码用 `@(...)` 数组会拼成一行）**

- **现象**：用 `@( $ind + 'a', $ind + 'b' … )` 组多行再 `InsertRange` 写回，落到文件里**全挤成一行**（元素间被空格连接）。若首行是 `//` 注释，**整段代码就被注释掉了** ✗ —— 这直接导致了"主题切换一直不生效""复制日志失效"两个 bug。
- **规矩**：批量写多行代码**一律用 here-string（`@'...'@`）再 `-split "`r`n"`**，不要用数组拼；写完**必须回读校验**（`Get-Content` 看前几行 / 扫"注释里带代码"的长行）。

## 2026-10-15　事故复盘：导入重复 + 开发范围失控（并立规则）

### 一、发生了什么

用户在 `v0.2\记账本`（已安装的 0.2.3）里对**同一个导入文件**先后导入了 3 次（10-13 22:13、10-15 04:02、10-15 04:07）。
按设计，重复导入应当"跳过重复"，**实际却把同一批账重复写进了账本**，用户手工删除了 9 条才恢复。

### 二、根因（有证据）

1. **判重键把「归属」算进去了**（`Core\Exchange.cs` 的 `DedupeKey` 含 `record.Owner`）。
   导入界面的「保存为谁」有「用文件里的 / 统一改为 / 清空归属」三种选择，用户两次导入选了不同项
   → 同一笔账一次带 `归属=ajmn`、一次为空 → **键不同 → 一条都没跳过**。
   证据：`备份\2026-10-14\20261015-040810-2026-10-14.jsonl` 里同时存在
   `001 10:28 支出/其他 20.00 归属=ajmn` 与 `005 10:28 支出/其他 20.00 归属为空`。
2. **判重只认"八个字段完全相等"**：备注写法不同（`转账-转给牢梅` ↔ `转账-转给牢梅（储蓄卡5632）`）、
   时间差几分钟（微信 `13:45` / 银行 `13:00`）都会被当成新记录。
3. **附带问题**：`配置\账户.json` 的用户码被改成了 `ajmn`（不是合法用户码 `u`+12 位 Base32），
   早期记录用的是 `u9CBMHVTZSWCW`，导致"谁的账"这一维度也不一致。

### 三、怎么修的

- 判重改为**三级指纹，且一律不含归属/来源/编号**：
  `FP0` 日期+时间+类型+分类+金额+支付方式+归一化备注；`FP1` 日期+类型+金额+支付方式+备注"相等或互相包含"；
  `FP2` 类型+金额+支付方式+备注，日期差 ≤1 天或时间差 ≤10 分钟 → 归为"疑似"。
  备注先归一化（全角转半角、去尾部括号）。
- 导入二次检查页新增**先一步检查**：逐行给出预判，预判不导入的整行浅色；
  每行左侧「状态」按钮可在 **自动 / 导入锁定 / 不导入锁定** 之间切换，改完立即刷新（含顶部计数）。
- 判重结果会在导入时按行执行（`Apply(preview, options, plans)`），疑似默认**不导入**、可手工改成"导入锁定"。

### 四、开发范围失控的问题
