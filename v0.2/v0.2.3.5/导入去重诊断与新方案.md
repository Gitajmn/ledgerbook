## 二、根因（三条，按影响排序）

1. **判重把「归属」算进去了**（主因）
   导入界面的「保存为谁」有「用文件里的 / 统一改为 / 清空归属」三种选择。你两次导入选了不同项 → 同一笔账的 `归属` 一次是 `ajmn`、一次为空 → **判重键不同 → 一条都没跳过**。

2. **判重只认"八个字段完全相等"**
   任何一个字段有一点差异就判为新记录。真实账单里这种差异极常见：
   - 备注写法不同：`转账-转给牢梅` ↔ `转账-转给牢梅（储蓄卡5632）`、`淘宝` ↔ `淘宝（数字人民币0088）`
   - 时间不同：微信记 `13:45`、银行记 `13:00`（两边记账时刻本来就会差）
   - `归属` 不一致（见根因 1）

3. **判重不区分"同一笔"和"相似的一笔"**
   现在只有"重复 / 不重复"两态。而现实中要区分三种：
   **同一条记录**（必须跳过）／**同一笔交易的不同记录**（应跳过）／**恰好金额相同的两笔真实消费**（绝不能拦，例如你 10-12 的 `霸王茶姬 20.00` 与 `微信红包-发给刘博雅 20.00`）。

### 附带发现（建议一并修）

- **用户码被改成了 `ajmn`**，它不是合法用户码格式（应为 `u` + 12 位 Base32）。这会让"谁的账"判断、跨设备导入的归属匹配长期不可靠。你早期记录用的是 `u9CBMHVTZSWCW`。
- 现在 21 条里：归属 `u9CBMHVTZSWCW` 2 条、空 13 条、`ajmn` 6 条 —— **元数据不统一**（不影响金额统计，但影响按归属筛选/合并）。

## 三、新算法方案：三级指纹 + 归属无关

### 设计原则

1. **归属/来源/编号 一律不参与判重**（它们只是元数据，不是这笔交易本身）
2. 判重分**三级**：能确定的跳过，不确定的**只提示、不擅自拦**
3. 预览界面**先把结果说清楚**（新增 / 跳过 / 疑似各多少条）
4. 同一批文件内部也要去重
5. 留一条**后悔路**：支持"撤销上次导入"

### 规范化（Normalize，判重前先做）

| 字段 | 规范化 |
|---|---|
| 日期 | `DateOnly` |
| 时间 | 分钟数（空 = 未知，单独处理） |
| 金额 | `decimal`，两位小数（不参与模糊） |
| 备注 | 去首尾空白、全角转半角、**去掉尾部括号内容**（`（储蓄卡5632）`、`(数字人民币0088)`）、折叠连续空格 |
| 类型/分类/支付方式 | 原样（不做模糊） |

### 三级指纹

| 级别 | 组成 | 命中后的动作 |
|---|---|---|
| **FP0 同一记录** | 日期 + 时间 + 类型 + 分类 + 金额 + 支付方式 + 归一化备注 | **跳过**（确定重复） |
| **FP1 同一笔交易** | 日期 + 类型 + 金额 + 支付方式，且归一化备注**相等或互相包含** | **跳过**（跨渠道/改了备注写法的同一条） |
| **FP2 疑似同一笔** | 类型 + 金额 + 支付方式 + 归一化备注，日期相差 ≤1 天 或 时间相差 ≤10 分钟 | **列为"疑似"**，默认**不导入**，由你在预览里勾选 |
| 提示（不算重复） | 同日 + 类型 + 金额（备注差很多） | 只在预览里**提示**（例如你 10-12 那两笔 20.00），**不拦** |

补充规则：
- **金额必须完全相等**（不设容差，避免把两笔不同的钱混成一笔）
- 时间未知（空）时，FP0 降级为"日期+类型+分类+金额+支付+备注"
- FP1 的"备注互相包含"用归一化后的字符串判断（保守：只在短的那条长度 ≥2 时启用）

### 界面（导入预览窗口）改成三段式

```
共 12 行：新增 2 条 ｜ 跳过 8 条（账本里已有） ｜ 疑似重复 2 条
[ 新增 ]  [ 跳过(8) ]  [ 疑似(2) ]      ← 三个页签
```
- 「疑似」页签：每条一行 + 勾选框（**默认不勾**），并显示它和账本里哪一条相似（时间/金额/备注并列对比）
- 冲突策略沿用现有设置（跳过重复 / 覆盖…），但**只有 FP0 允许"覆盖"**；FP1 只跳过、FP2 只由你勾选

### 可选增强（建议做，成本不高）

1. **撤销上次导入**：导入成功后写 `日志\导入批次-<时间>.json`（记下本次新增的记录编号）→ 设置页出现「撤销上次导入」按钮。**这次的痛苦就能一键回退**。
2. **记录指纹字段（数据格式 v4，可选）**：给每条记录存一个 `指纹`（FP0 的哈希）。老记录没有该字段时按需现算，**不强制迁移**，命中更快也更稳。

### 验收用例（用你这次的真实数据做回归）

| 用例 | 期望 |
|---|---|
| 同一文件导入两次，一次「统一改为 ajmn」、一次「用文件里的」 | 第二次 **全部跳过**（旧算法：全部重复写入 ✗） |
| `转账-转给牢梅` vs `转账-转给牢梅（储蓄卡5632）`，同日同金额同支付 | FP1 **跳过** |
| `淘宝` vs `淘宝（数字人民币0088）` | FP1 **跳过** |
| `麦当劳 35.50` vs `麦当劳 36.50` | **不判重** |
| 同日两笔 `20.00 微信 餐饮`（霸王茶姬 / 微信红包-发给刘博雅） | **不拦**，仅在预览提示 |
| 同一条记录、归属一个有一个无 | FP0 **跳过** |

### 改动点（代码）

| 文件 | 改动 |
|---|---|
| `Core\Exchange.cs` | `DedupeKey` 拆成 `Fingerprint0/1/2`（都不含归属）；`FindDuplicate` 改为返回 `(级别, 命中记录)`；导入循环按级别决定 跳过/记疑似 |
| `Core\Exchange.cs`（`ImportPreview`） | 增加 `Skipped`（已存在而跳过）、`Suspects`（疑似，含与之相似的账本记录）两个列表 |

| `App\SettingsPanel.cs` | （可选）「撤销上次导入」 |
| `Core\Log.cs` | （可选）导入批次记录 |
