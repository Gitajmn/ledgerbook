# v0.2.6.5 本次修改

> 0.2.6 之后的测试版（D 位 = 测试位）。起因：用户 2026-10-24 报「记账本后台还在运行，但
> 任务栏、托盘都没有入口」，查下来主窗口被系统隐藏了，而程序既没有托盘图标，
> 单实例的「调出已有窗口」又依赖 `MainWindowHandle`（隐藏时为 0）→ 彻底无入口。

## 一、改动清单

| # | 项目 | 现象/需求 | 成因 | 修法 | 状态 |
|---|---|---|---|---|---|
| 1 | 新增托盘图标 | 用户要求：双击/左键 → 调出主窗口；右键 → 打开主界面 / 更新内容 / 退出 | 0.2.x 从来没有托盘图标（源码里没有任何 `NotifyIcon`/`Shell_NotifyIcon`；v0.1 的 Python 版也没有）。窗口一旦被隐藏就零入口 | 新增 `App\TrayIcon.cs`：`Shell_NotifyIconW` + 一个**普通隐藏窗口**收回调（`HwndSource`，`WS_EX_TOOLWINDOW|WS_EX_NOACTIVATE`）；图标取自本程序 exe（`ExtractIconEx`，取不到退回系统默认）；右键菜单用 Win32 `TrackPopupMenu`（3 项：打开主界面 / 更新内容 / 退出） | ✅ 逻辑已验证（见下）；图标本体在沙箱内无法注册（见「未能验证」） |

## 二、证据（`临时\托盘验证-数据\`，用真账本副本跑，不碰用户账本）

用 `PostMessage` 直接给窗口发消息，绕开鼠标（沙箱里点不了）：

```
① 设置开「关闭时最小化到托盘」→ 给主窗口发 WM_CLOSE
   主窗口 可见=False   进程还在=True
   日志：关闭主窗口 → 收到托盘（设置里开了「关闭时最小化到托盘」）          ✅

② 给托盘消息窗口发 WM_TRAY + WM_LBUTTONUP（模拟左键）
   主窗口 可见（前）=False →（后）=True
   日志：托盘：左键/双击 → 调出主窗口                                    ✅

③ 窗口藏起来后，再启动第二个实例（模拟用户又双击了图标）
   第二个实例：0.3 秒退出、退出码 0
   主窗口 可见（前）=False →（后）=True     进程数=1
   日志：已经有一个记账本在运行 → 已把它调到前台                          ✅
   ← 这正是用户 2026-10-24 卡住的场景，现在能自救了

④ 设置关掉「关闭时最小化到托盘」→ 发 WM_CLOSE
   进程还在=False    残留进程数=0                                       ✅（点 ✕ 仍是直接退出）
```

设置页截图：`临时\托盘验证-数据\设置-托盘开关.png`（布局：外观 / 界面字号 / 货币符号 / 数据目录 / **托盘图标**）。

## 三、未能验证（如实说明）

**托盘图标本体（右下角那个小图标）在沙箱里加不上去**：
`Shell_NotifyIcon` 返回 false，日志错误码 **5（拒绝访问）**，结构体 976 字节（x64 正确值）、
图标句柄非 0。原因是本机执行环境为 **Low 完整性**（`whoami /groups` 显示 `Low Mandatory Level`）
且这台机器上 `explorer.exe` 没有在跑 —— UIPI 会拒绝低完整性进程往通知区域加图标。
正常双击启动（Medium 完整性、explorer 在跑）应当能加上，但**这一条我无法在本机截图证明**，
需要用户实际启动后看一眼；若图标没出现，运行日志里那行「托盘图标创建失败：错误码 N」就是线索。

顺带修正的踩坑：最初用 `HWND_MESSAGE`（消息专用窗口）接托盘回调，同样被拒；
改成普通隐藏窗口（无 `WS_VISIBLE`）后错误码才稳定收敛到 5（即纯粹是完整性级别问题）。
