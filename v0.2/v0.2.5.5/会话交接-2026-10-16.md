## 1. 铁律（违反过，别再犯）

1. **不碰用户数据**。`v0.2\记账本\`（他自用）里的 `数据\` `配置\` `导出\` `备份\` 一律只读；
   要改必须：先备份 → 说明依据 → 逐条核对 → 给回退路径 → 事后报告。**状态文件也算数据**（如 `配置\上次运行版本.txt`）。
2. **新版本只在上一版的 `.5` 文件夹里开发**（0.2.5 → `v0.2.5.5\`）；正式交付物放 `v0.2\<版本>\`。
3. **发布顺序固定**：改版本号 → 打包 → **自检（退出码必须 0）** → 归档 → **改 README（仓库首页）** → 提交/推送 → 建 Release + 传附件。
4. **打包/发布要用户点头**。他常说"打包发版"才做；不擅自打包、不擅自上传。
5. **改完必须回读**（尤其用脚本插代码）—— 我在这次会话里因为"插入点"错了 **6 次**。
6. **不要凭感觉说"修好了"**：要么跑出证据（测试输出 / 截图），要么明确写"未验证"。
7. **不要用 `--screenshot` 验证"自动弹窗"**：截图模式会 `SuppressWhatsNew`，弹窗被抑制 → 会得出错误结论。
8. **不要启动会阻塞的 GUI 进程**（工具调用会被中止）；要跑 GUI 用后台任务 + `Stop-Process`。
9. **PowerShell 补丁脚本的单引号/双引号**：`$`、`$global:`、`$LASTEXITCODE` 在**双引号**里会被展开 → 追加内容一律用**单引号 here-string** `@'…'@`，并给 .ps1 写 **UTF-8 BOM**。
10. **对话软件给的数据**：允许"多笔合并成一行"（用户要求简洁、靠总额核对）。模板第 12 条已写明：合并可以，但**备注要写清笔数、时间要写区间**（如 `15:35-15:55`）。时间区间我们已能容忍（取开始时刻）。

## 3. 数据格式（v3）

JSONL，一行一条，字段带名字；空字段不写进文件：
```
日期(来自文件名) 编号 时间 类型 分类 金额 支付方式 备注 详细备注 归属 来源 单位
```
- `编号` = `YYYYMMDD-NNN`（一天内唯一，**这条铁律靠 `Apply` 里的"撞车就换新号"保证**）
- `归属` = 用户码（`u`+12 位 Base32）；`来源` = 设备名；`单位` = **v0.2.5 新增**（可缺省；空 = 用设置里的默认单位）
- 交换 CSV 表头：`日期,编号,时间,类型,分类,金额,支付方式,备注,详细备注,归属,来源,单位`（UTF-8 **带 BOM** + CRLF）
- 金额**永远纯数字**（两位小数）；单位只用于显示/统计口径，绝不参与金额解析

## 4. 导入判重：**当前语义（改过四次，以这里为准）**

| 判定 | 会导入？ | 条件 |
|---|---|---|
| `Duplicate` | **不导入** | `Fingerprint0` 完全一致（日期+时间+类型+分类+金额+支付+备注），**且按次数扣减**：账本里原本有几条一样的，最多跳过几条 |
| `Similar` | **默认导入** | ① FP1（同天+类型+金额+支付+备注相近）**且** 相隔 ≤10 分钟；② FP2（类型+金额+支付+备注）+ `CloseMatch`（实际相隔 ≤120 分钟；或隔一天但钟点几乎相同） |
| `New` | 导入 | 其他 |

- **同一批内部不算"账本里已有"**（`Remember(candidate, countAsExisting: false)`） →
  一次导入里 56 笔相同红包会**全进**（这是用户真实场景）。
- **绝不擅自划掉**：用户的原话是"连续几天同额同备注的转账被自动划掉了" → 现在只有"确实同一条 + 次数用尽"才跳过。
- 判重**不看** `归属/来源/编号`（老代码把它们算进键里，导致重复导入 —— 那是 0.2.3 的病根）。
- 判重范围：`ImportWindow.ReadExistingAround()` = 候选日期**所在整月**（跨天重复也能看见）。

## 5. 发布流程（照着做，别改顺序）

```powershell
# 0) 目录：新版本放上一版的 .5 里；正式交付物放 v0.2\v<版本>\
# 1) 改版本号
#    v0.2\Directory.Build.props  →  <Version>0.2.6</Version>
# 2) 建交付目录并放公告（打包脚本会读 v0.2\v<版本>\更新公告.md → 打成 更新内容.txt）
# 3) 打包（约 4 分钟，产物在 v0.2\v<版本>\安装包\ + 便携版\）
pwsh -File v0.2/工具/打包-自研安装包.ps1
# 4) 自检（约 3 分钟，**必须退出码 0**）
pwsh -File v0.2/工具/安装包自检-甲.ps1 -含应用自检
# 5) 归档（→ 历史版本\v<版本>-存档-<日期>\）
pwsh -File v0.2/工具/存档版本.ps1 -追加说明 "…"
# 6) 源码快照
pwsh -File v0.2/工具/测试版快照.ps1
# 7) **改 README（仓库首页）**：当前版本 / 公告链接 / 更新要点 / 安装包说明版本号
# 8) 提交推送（见下）
# 9) 建 Release + 上传 4 个 ASCII 名附件
gh release create v0.2.6 --repo Gitajmn/ledgerbook --title "记账本 v0.2.6" --notes-file "v0.2\v0.2.6\更新公告.md" --latest
# 附件必须 ASCII 名（中文名会 404）：ledgerbook-0.2.6-setup-full.exe / -setup-small.exe / -portable-full.zip / -portable-small.zip
#    前端用 --clobber 覆盖
```

**git 推送**（这台机器的沙箱禁止命名管道，git 的凭据助手起不来）：
```powershell
$tok = (& gh auth token).Trim()
$u = 'https://Gitajmn:' + $tok + '@github.com/Gitajmn/ledgerbook.git'
git -c http.version=HTTP/1.1 -c credential.helper= fetch $u main
git reset --soft FETCH_HEAD          # 先吃掉远端新提交，避免 non-fast-forward
git add -A                           # 或按需
git commit -m "…"
git -c http.version=HTTP/1.1 -c credential.helper= push $u main
```
> 顺序很重要：**先 fetch + reset --soft，再 add + commit**；反了会出现"提交了但删除没进去"（我踩过）。
> 远端分叉时也能用 Contents API / Git Data API 兜底。

## 9. 踩坑清单（这条最省时间）

| 坑 | 事实 |
|---|---|
| 插代码插错位置 | **6 次**。`edit` 工具/脚本把新行插到 `if` 和它的 `{` 之间、或插成重复签名、或插成独立语句。**改完必须回读那一段** |

| PowerShell 注释写成 `//` | 那是 C# 的；PS 用 `#` |

| git push 失败 | 见第 5 节：令牌放 URL + `http.version=HTTP/1.1` + `credential.helper=` |
| Release 附件 404 | 中文文件名必 404 → ASCII 名 |
| 单实例锁挡住自动化 | 已在 `Program.cs` 修：带自动化参数时跳过 |
| `--screenshot` 会抑制更新公告 | 验证弹窗要看**日志**，不能靠截图 |
| 公告/模板里写 `**加粗**` | 应用里是纯文本 TextBox，会露星号 → **一律不许有 `**`** |
| 公告从哪来 | 打包脚本读 `v0.2\v<版本>\更新公告.md` → 打成程序里的 `更新内容.txt` |
| 版本号被谁读 | 自检脚本会读 `Directory.Build.props` → **自检跑完再改版本号** |
| 月度汇总口径 | 结余是 `Income − Expense` 派生的 → 按单位过滤后口径自动一致 |
