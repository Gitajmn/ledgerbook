# 记账本 · 开发规则（必须遵守）

> 立此文档的原因：2026-10-15 的 0.2.3.5 开发期间，我（AI）连续多轮改动把范围搞乱了，
> 并且旧的去重逻辑（把「归属」算进判重键）导致用户**同一个文件重复导入、账本出现大量重复**，
> 用户只能手工删除。以下规则为硬性约束，任何一次改动前都要先对照本文档。

## 一、版本与目录（最重要）

1. **新版本只在"上一版的 `.5` 文件夹"里开发。**
   例：`0.2.3` 之后的测试版 = `v0.2\v0.2.3.5\`，版本号 = `0.2.3.5`（`A.B.C.D`，D 是测试位）。
   **不得**另建别的版本号文件夹（如 `0.2.4`、`0.2.3.6`），**不得**擅自"发布"任何新版本。
2. **打包前不要在新版本文件夹里零散改动。**
   要改就一次性改完、重新出运行目录与源码快照；**打包（归置）之后**若还要改，
   必须先说明"为什么要改、改哪里、影响什么"，得到用户明确同意后再动。
3. **已发布的旧版本目录（如 `v0.2\v0.2.3\`）视为只读**，不得修改、不得覆盖。
4. **用户的实时账本目录（如 `v0.2\记账本\`）默认视为只读**：
   只有在用户**明确指出**要清理/导入/恢复时才能写，且必须先备份并给出回退路径。

## 二、改动流程

5. 每次改动都要在**当前版本的 `本次修改.md`** 里按编号记录：**编号 / 现象或需求 / 成因 / 修法 / 状态 / 证据**。
   没有证据（截图、日志、核对结果）就不能写"已验证"。
6. 改完代码要**重新出源码快照**（`工具\测试版快照.ps1`），保证快照与代码一致。
7. 工具/临时脚本放 `v0.2\工具\` 或 `临时\`，**不要**留在发布目录里。
8. 修改脚本（PowerShell）必须带 **UTF-8 BOM**；改代码时**不得在遍历中插入行**（会死循环写坏文件）；
   改动前**先备份原文件**，并且每处替换都要先校验"只命中一次"。

## 三、数据与隐私

9. **不得擅自修改用户数据**（账本 JSONL、`配置\*.json`）。
   需要清理/重建时：① 先备份到 `临时\记账本-数据备份-<时间>\` ② 说明依据（用哪份导出、哪些行）
   ③ 改完逐条核对（条数、日期、时间、金额）④ 报告回退路径。
10. 日志里**不写备注/详细备注原文**（只写类型、分类、金额这类定位信息）。
11. 打包、发布、上传仓库、发送邮件等**对外动作**，必须经用户明确同意后才能做。

## 四、范围（当前生效）

| 可以改 | 不可以改 |
|---|---|
| `v0.2\src\**`（代码，当前测试版范围内） | `v0.2\v0.2.3\**`（已发布，只读） |
| `v0.2\v0.2.3.5\本次修改.md`、`开发日志.md`、`源码快照\` | `v0.2\记账本\**`（用户实时数据，除明确要求） |
| `v0.2\工具\**`、`临时\**` | 新建版本目录 / 新版本号 / 新安装包（须先问） |

## 五、沟通约定

12. 界面类改动必须给**截图证据**（浅色/深色/自定义至少各看一次）；做不到就明确写"未验证"。
13. 无法验证的部分要**如实说明**，不许"看起来没问题"就当作通过。
14. 用户提出的澄清优先于我的推断：例如"UI 用旧版的"→ 就保留旧控件外观，不要自创一套。
15. 长任务分步做，每步结束给一句状态；**不要启动会阻塞的 GUI 进程**（会被工具中止）。

## 六、发版提醒（务必照做）

**打包 0.2.4 时**（用户 2026-10-15 明确要求）：
1. 先把版本号改好：`v0.2\Directory.Build.props` 的 `<Version>` → `0.2.4`；
2. 交付物放 `v0.2\v0.2.4\`（安装包 / 便携版 / 更新公告 / 本次修改 / 源码快照 / README）；
3. 更新公告可直接复用 0.2.3.5 那份（标题与「本版为 0.2.4 正式版」已经写好）；
4. 0.2.3.5 那份公告与包**不要再改**（用户已裁定）。

## 七、GitHub 与网络（2026-10-15 补充）

16. **推送失败就改走 API，并记录分叉状态。**
    `git push` 在本机经常被网络重置（`Connection was reset` / `Could not connect to server`）。
    - 单文件改动 → 用 **Contents API**：`gh api -X PUT repos/<owner>/<repo>/contents/<path> -f message=… -f content=<base64> -f sha=<当前sha>`
    - 多文件/整树 → 用 **Git Data API**（blobs → tree → commit → 更新 ref）
    - **必须记下本地与远端的提交号**；内容一致但提交不同时，等网络恢复后执行：
      `git fetch origin main ; git reset --hard FETCH_HEAD`
17. **git 的凭据助手在本机会失败**（沙箱禁止命名管道 → `sh.exe: couldn't create signal pipe`；表现为 `could not read Username`）。
    正确做法：**把令牌放进远端 URL**（命令里只用变量、令牌不落命令行；用完即删临时文件）：
    `git -c http.version=HTTP/1.1 -c credential.helper= push https://<user>:<token>@github.com/<owner>/<repo>.git main`
18. **GitHub Release 附件不支持中文文件名**（上传返回 `HTTP 404`）。附件一律用 **ASCII 名**：
    `ledgerbook-<版本>-setup-full.exe` / `-setup-small.exe` / `-portable-full.zip` / `-portable-small.zip`；
    本地交付物保持中文名，发布时再复制成 ASCII 名。覆盖同名附件用 `gh release upload … --clobber`。

## 八、打包链（2026-10-15 补充）

19. **发版只能用"链 A"**：`v0.2\安装器\记账本安装器.cs` + `工具\打包-自研安装包.ps1`
    （产出 `记账本-安装包-v<版本>-单文件-完整.exe` / `-小包.exe`，**支持 `--silent`**，自检脚本依赖它）。
    另一条"链 B"（`src\LedgerBook.Setup\Installer.cs` + `工具\打包免NET负载.ps1`）**没有 `--silent`**，不能用于发版。
20. 打包前必须备好两样东西（缺了会直接失败）：
    `临时\nuget-离线\` 里的两个运行时包（`microsoft.netcore.app.runtime.win-x64.<版本>.nupkg`、
    `microsoft.windowsdesktop.app.runtime.win-x64.<版本>.nupkg`，可从 `LB-构建工具链\nuget-packages\` 复制）
    以及 `临时\NuGet-离线.Config`。
21. **更新公告必须随负载进包**（`更新内容.txt ← 更新公告.md`）—— 两条链的脚本里都要有这一步，
    否则装好后「更新内容」窗口只能显示兜底文字。
22. 打包脚本里的版本变量名**不统一**：`打包-自研安装包.ps1` 用 `$版本`，`打包免NET负载.ps1`、
    `打包单文件安装包.ps1` 用 `$version` —— 动手前先 `Select-String` 确认。
23. **源码丢失可从 `源码快照\` 恢复**（本轮 `v0.2\安装器\` 就是这样救回来的）。
    任何删除/清理动作之前，先确认快照里有它。

## 九、验证方法（2026-10-15 补充，都是本轮踩出来的）

24. **不要用 `--screenshot` 去验证"自动弹窗"**：截图模式会设置 `SuppressWhatsNew`，
    自动弹窗被抑制，日志里那行判定也不会出现 —— 会得出错误结论。
    正确做法：**后台启动应用、等几秒、`Stop-Process` 杀掉，然后读运行日志**。
25. **"能不能滚动"要看截图里有没有滚动条**。WPF 里 `StackPanel` 会给子元素**无限高度**，
    文本框会被撑到全文高度、滚动条永不出现 —— 能滚动的容器要用 `Grid`（Auto / **\*** / Auto）。
26. **"首次安装 vs 老版本升级"不能只靠新引入的状态文件判断**：
    新状态文件在老版本安装里根本不存在，会被一律误判成"首次安装"。
    要用**用户数据的客观痕迹**（数据目录里有没有账、备份目录是否非空）来区分。
27. **判断"本机已装版本"必须限定到目标目录**：注册表是全局的，
    别的目录做过的测试安装（版本更高）会让本次安装误弹询问。
    顺序：目标目录的 exe → 目标目录的 `安装信息.txt` → 注册表（且 `InstallLocation` 必须与目标一致）。
28. **自检脚本会读 `Directory.Build.props` 的版本号** → **改版本号前必须等自检跑完**。
29. **发布门槛 = 自检三段全绿且退出码 0**：离线逻辑（35 项）+ 甲安装器真装真卸（含大包/小包各更新一次、
    运行时时间戳不变、更新后设置与账户字节一致）+ 应用数据层（96 项）。

## 十、PowerShell / C# 编辑（补充）

30. 补丁脚本必须写 **UTF-8 BOM**（否则 PS 5.1 按 GBK 读成乱码）。
31. **单引号串里不能用 `\'` 转义**（PS 的规则是 `''`）→ 生成 C# 代码时**避免单引号字符**，
    用 `(char)0x…` / 双引号代替。
32. **双引号串里的 `$global:`、`$LASTEXITCODE` 等会被变量展开** →
    追加脚本内容一律用**单引号 here-string**（`@'…'@`）。本轮就因为这条把
    `$global:LASTEXITCODE = 0` 写成了 ` = 0`，脚本直接语法错误。
33. **不要在遍历中插入行**（会死循环写坏文件）；按行号插入时**先把所有行号算完再改**。
34. `return $list` 会把 `List<T>` 展开成**定长数组** → 用 `New-Object` 后 `[void]$Add()`。
35. **插入点紧邻 `if (…)` 时极易插进块内部**（本轮在 `Program.cs` 上犯了 3 次同样的错）→
    **改完必须回读那段代码确认缩进与括号层级**。
36. **不要启动会阻塞的 GUI 进程**（工具调用会被中止）→ 要跑 GUI 就用**后台任务 + 定时 `Stop-Process`**。

## 十一、用户数据与状态文件

37. **状态文件也是用户数据**（如 `配置\上次运行版本.txt`）→ 需要删除/修改时**先问用户**，不要擅自处理。
38. 动用户数据必须：① 先备份到 `临时\记账本-数据备份-<时间>\`
    ② 说明依据（用哪份导出、哪些行）③ 改完**逐条核对**（条数、日期、时间、金额）④ 报告回退路径。

## 十二、发布顺序（固定流程）

39. ① 改 `Directory.Build.props` 的 `<Version>` → ② `工具\打包-自研安装包.ps1`（退出码须为 0）
    → ③ `工具\安装包自检-甲.ps1 -含应用自检`（三段全绿、退出码 0）
    → ④ `工具\存档版本.ps1`（归档到 `历史版本\v<版本>-存档-<日期>\`）
    → ⑤ 提交并推送源码（失败则走 API，见第 16 条）
    → ⑥ 建 Release（`gh release create`）+ 逐个上传 ASCII 名附件（`--clobber` 覆盖）。

## 十三、发版必须同步仓库首页 + 旧版清理规矩（2026-10-16 补充，用户明确要求）

40. **每次打包发版，必须同步更新仓库首页 `README.md`（GitHub 仓库首页）。**
    至少改三处：① 顶部「当前版本」与「更新公告」链接（指向 `v0.2/v<版本>/更新公告.md`）；
    ② 「本次更新要点」整段换成这一版的（简述功能，底层修复可归并）；③ 「安装包说明」标题里的版本号
    （包体大小有变化也一并改），需要时补一节新功能说明（如 v0.2.5 的「单位」）。
    因此**固定发布顺序**更新为：
    改版本号 → 打包 → 自检 → 归档 → **改 README（仓库首页）** → 提交/推送 → 建 Release + 传附件（ASCII 名）。
    推送失败一律走 API 兜底，并记下本地与远端提交号（见第 16、17 条）。

41. **旧版本清理规矩**：只有在两个备份都齐了之后，才清理 `v0.2\` 里旧版本目录占用的空间 ——
    ① 本机完整归档 `历史版本\v<版本>-存档-<日期>\`（必须有逐文件 SHA256 的「存档清单.txt」）；
    ② 远端备份（有 Release 的看附件；没有 Release 的把源码快照放进 `v0.2\文档备份\源码快照\v<版本>\`）。
    清理时**只删未被 git 跟踪的文件**；被跟踪的文档与源码快照要么保留，要么先复制到 `v0.2\文档备份\` 再删。
    删除前必须逐条核对目标的绝对路径确实在 `v0.2\` 下，删完检查 `git status` 不应出现删除变更（除非是有意提交的删除）。
    最近三个发布版与当前开发目录（上一版的 `.5` 文件夹）**不清理**。
