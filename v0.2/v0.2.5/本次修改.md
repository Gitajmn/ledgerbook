## 追加：单位（货币符号）注入问题 + 单位改随记录走 + 其他分类冲突（2026-10-15）

### 4️⃣ 单位输入形同虚设（用户报"注入"）

**现象**：设置 → 通用 →「货币符号」只校验**长度 ≤ 4**；输入 `321` 会被接受 →
之后**每个金额都显示成 `32112.00`**（用户说的"记账录入数据改变"）；输入 `(1==0)` 因超长被拒、边框变红但没有说明。

**澄清（查证结论）**：**存储与导出的金额始终是纯数字**（`Storage` 存 `12.00`；`Summary.ExportCsv` 写 `0.00` 格式；
`Exchange` 导出也不带符号）→ 所以 321 **不会**污染落盘数据；危害是**显示严重误导** + 校验无意义。

**修法**：Core 新增 `UnitRule`（非空、≤6 字、不含空格换行；**不做**"只许字母/只许符号"的限制 →
单位保持开放：元 / € / USD / 积分 / 小时 都行）；设置页与记一笔都用它校验，
**并明确告诉用户为什么没改**；纯数字单位**只提示不阻止**。

### 5️⃣ 单位改成"记录自己的属性"

- `Record` 新增 `单位` 字段（`Fields.Unit` + 表头 + 读写 → **CSV 导出/导入自动带上单位列**）
- `Storage.Append` 新增可选 `unit`：**留空 = 用当前默认单位**（设置里的货币符号）
- 记一笔：金额旁新增**单位输入框**（默认=默认单位，可逐笔改）
- 查询统计：新增**单位下拉**（全部单位 + 范围内出现过的单位）；
  **统计与绘图只算当前单位**（合计行标注口径），**明细列表仍列出全部单位并逐行显示各自单位** ← 用户要求
- `QueryFilter.Unit` + `Query.Matches` 里按单位过滤（空单位的记录算默认单位）

### 6️⃣ 分类下拉消除"其他"冲突

同名分类分属收入/支出时（经典例子「其他」），下拉显示为「其他（支出）」「其他（收入）」；
明细过滤仍用**裸分类名**，图表高亮用「收入·其他」这类标签（`_statsCategoryLabel`）。

**Core 测试**（`临时\导入重复检验\`）：

## 追加：注入面彻底查证（用户追问"关于注入口的问题修改了吗"）

### 结论一：**代码注入不可能**，且已查证

- 全项目**没有**任何把字符串当代码执行的路径：`Process.Start` / `cmd.exe` / `powershell` / `Assembly.Load` / `Compile` / `Eval` **一处都没有**；
  搜到的 `Invoke(` 全是 UI 回调委托（`AfterShown?.Invoke()` 之类），与用户输入无关。
- 设置文件走**真正的 JSON 序列化**（`Settings.Save(path) => Table.AtomicWrite(path, Json.Pretty(_root))`）→
  单位里写 `"`、`\`、`{`、`}` 都会被正确转义。实测：把单位设成 `"}` → 保存后读回正常、程序不崩、配置不坏。
- 金额落盘始终是纯数字：实测把单位设成 `(1==0)` 再记一笔，落盘金额仍是 **321.00**，单位只是显示用的字符串。

### 结论二：**确实存在一个真注入面 —— 导出 CSV 的公式注入**，本轮已修

**风险**：Excel / WPS 打开 CSV 时，**以 `=` `+` `@` 开头的单元格会被当公式执行**。
而备注、分类、支付方式、单位这些是自由文本（现在单位还能逐笔写）→ 导出给别人的文件或自己双击用 Excel 打开，
就可能执行其中的内容（CSV/公式注入，业界公认风险）。

**修法**：
- `Exchange.Escape`（导出唯一出口）：对 `=` `+` `@` `\t` 开头的单元格加**单引号前缀**（Excel 视为纯文本）；
  以 `-` 开头但**不是数字**的也加；**金额这类纯数字一律原样保留**（不受影响）。
- `Record.Set`（导入入口）：只在该"单引号 + `=`/`+`/`@`"组合下**去掉**那个前缀 → 导出/导入**往返一字不差**；
  备注里正常的撇号（如 `'abc`）不受影响。
- 月度汇总 CSV 只含数字与固定词（日期/星期/合计），无自由文本 → 无需处理。

### 证据（`临时\导入重复检验\`，退出码 0）

```
单位 [(1==0)] 规则：通过        ← 5 字，按"单位开放"原则接受
单位 [=1+1] 规则：通过
单位 [=cmd|'/c calc'!A1] 规则：拒绝（单位最多 6 个字（现在 17 个））
单位 [@SUM(1)] 规则：拒绝（单位最多 6 个字（现在 7 个））
单位 ["] [}] [\] 规则：通过      ← 会被 JSON 正确转义
写入后：金额=321.00（应为 321.00）　单位=(1==0)
设置里塞 "}  之后读回：¥（没崩就说明 JSON 转义正确）
导出文件里还有裸露的 =/+ 开头单元格吗：False（应为 False）
导出里带单引号保护的例子：2026-10-13,20261013-002,14:00,支出,'=1+1,5.00,'+1,'@x,,,,¥
往返一致（=1+1 / +1 原样回来）：True
结论：通过 —— 危险字符串既不执行、也不改数据，导出被中和且能原样往返
```

### 关于"输入 (1==0) 弹 error"的说明

那是**旧版**的行为：`CurrencyInput` 只检查"长度 ≤ 4"，`(1==0)` 有 5 个字符 → 被拒 + 边框变红（没说明原因）。
本版已改为 `UnitRule`（≤6 字、非空、不含空格换行）并**明确显示拒绝原因**；`(1==0)` 现在会被接受，
但它**只是显示字符串**，既不执行也不影响金额。
