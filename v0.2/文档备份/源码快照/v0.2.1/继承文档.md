## 3. 安装包体系：设计与血泪坑（**最重要的一节**）

### 3.1 为什么不能用常规安装器
用户机器上 **`%TEMP%` 拒绝任何程序创建文件夹**（`Error 5 拒绝访问`；`icacls` 显示权限正常，疑似安全软件/受控文件夹访问）。
**所有**常规安装器第一步都要往 `%TEMP%` 解压自己 → 必然失败：
- **IExpress（wextract）**：静默退出/存根卡住 + 锁文件（详见 3.4）
- **Inno Setup 6**：报 `Setup was unable to create the directory "...\Temp\is-XXXX.tmp"`（实测截图）

### 3.2 最终方案：自组装单文件 exe（**不碰 `%TEMP%`**）
容器 v2（见 `工具\组装安装包.py` 与 `src\LedgerBook.Setup\PackageTail.cs`，两处必须一致）：
```
[stub.exe (17KB)]        .NET Framework 4.8 WinForms 解包器（Windows 都预装）—— 物理顺序就是这些
[wizard-slim.zip]        框架依赖向导（0.4MB）：已装 .NET 8 时用它，向导自己就能跑
[wizard-full.zip]        自包含向导（0.4MB）：没装 .NET 时用它，运行时由 payload-full 提供
[payload-slim.zip]       精简负载（0.4MB）：本体（用系统 .NET）
[payload-full.zip]       自包含负载（61.9MB）：本体 + 内置 .NET 8 运行时
[footer 40B]             "LBSETUP2" + int64×4 = {full, slim, wizardFull, wizardSlim} 长度
```
解包器是**从后往前**按 footer 里的长度切段的（所以物理顺序与 footer 里的记录顺序正好相反）。
- 组装：`工具\打包单文件安装包.ps1`（编/取两套向导 + csc 编解包器 + `工具\组装安装包.py` 拼装并回读校验）
- 解包器逻辑（`安装器\Installer.cs`，**C# 5 语法**，`=>`/`$""`/`?.` 都会编译失败）：
  1. **已有向导在跑**（锁文件被占）→ 把它的窗口叫到前台就退出，**不再解压**（避免撞锁报"正由另一进程使用"）
  2. 读尾部 40B → 校验 `LBSETUP2` → 算出各段偏移
  3. **有 .NET 8 桌面运行时** → 只解 `wizard-slim`（**快路**：0.4MB，秒开）；
     **没有** → 解 `payload-full`（向导的运行时就靠它）+ `wizard-full`
  4. 工作目录**已就绪**（`lb-setup-ready.txt` 里 mode/sizes 与当前一致）→ **跳过解压**直接启动向导
  5. 启动 `lbsetup.exe --setup "<安装包路径>"` → **立刻退出**；向导据此**直接从安装包尾部切负载**
  6. 退出前在工作目录**外面**放独立延迟清理脚本 `lb-setup-清理.cmd`（纯 ASCII 正文，路径当参数传）
- **关键点（本轮才真正做到）**：向导的 `lbsetup.runtimeconfig.json` 必须是 **`includedFrameworks`** 版本，
  否则它在没装 .NET 的机器上起不来。做法：**向导和应用都做真正的自包含发布**
  （`dotnet publish -r win-x64 /p:SelfContained=true`），`payload-full.zip` 就是应用的自包含产物
  （146 MB 展开 / 61.9 MB 压缩，含 `hostfxr.dll` `coreclr.dll` `hostpolicy.dll`），
  `wizard-full.zip` 是自包含向导本体，`wizard-slim.zip` 是框架依赖向导本体。
  实测 trace：`Executing as a self-contained app as per config file [<目录>\记账本.runtimeconfig.json]`（§7.1 有完整证据）。
- **`%TEMP%` 禁用**：解包器、向导、卸载器脚本、证书脚本**全部**不写 `%TEMP%`。
- 组装产物：`LB-v2.0\安装器\LedgerBook-Setup.exe`（每轮打包后会同步成最新的那一个包）。

### 3.3 权限与签名
- 用户机器**非管理员无法写工作区外目录** → 向导 exe 加 `app.manifest`：`requestedExecutionLevel level="requireAdministrator"`（**双击自动请求 UAC**）。
  代价：自动化截图 `--shot` 也会弹 UAC（测试时注意）。
- 安装时由向导调用 PowerShell：生成自签名证书 `CN=ajmn`（若不存在）→ `Export-Certificate` → `Import-Certificate` 到
  `Cert:\CurrentUser\Root` + `Cert:\CurrentUser\TrustedPublisher` → `Set-AuthenticodeSignature` **给装好的 `记账本.exe` 签名**；
  结果写入 `安装目录\安装信息.txt`（失败不影响安装）。
- **自签名挡不住 SmartScreen**（信誉机制）；只能解决 UAC 显示"未知发布者"与本机信任。彻底消除需买正规 OV/EV 证书。

### 3.4 IExpress 的三个坑（若还要用）
1. **必须** `AppLaunched=cmd.exe /c install.bat` —— 直接给 `.bat` 它自动套 `command.com`（系统没有）→ 报"创建进程时出错"。
2. **静默参数**：`ShowInstallProgramWindow=0` + `HideExtractAnimation=1`；用 `=1`（自带进度窗）会**卡死**。
3. 卡死的 `wextract` 进程**锁住安装包** → 必须先按**进程镜像路径**找到并 kill（`Get-Process | ? Path -like "<目录>*"`），否则删不掉文件。

### 3.5 批处理与编码（踩过两次）
- **含中文路径的 .bat 必须存为 GBK(936)** 并首行 `chcp 936`；存 UTF-8 时 cmd 会把中文路径读成乱码 → 删除**全部静默失败**（表现为"removed 只对英文名生效"）。
  - **本轮更稳的做法**：脚本正文写成**纯 ASCII**，中文路径**当命令行参数传**（`cmd /c ""脚本" "中文路径""`）——
    cmd 读文件按代码页，但命令行参数是 Unicode 转过来的，不会乱。三处清理脚本现在都是这么做的。
- **PowerShell 5.1 的 .ps1 带中文注释 → 必须存 UTF-8 带 BOM**（本机 shell 就是 5.1）。
  没 BOM 会被按 GBK 读成乱码并报"字符串缺少终止符""意外的标记"这类怪错。
  ⚠️ 用编辑器/`edit` 工具改过 `.ps1` 之后 BOM 可能掉，改完补一句：
  `[System.IO.File]::WriteAllText($p, [System.IO.File]::ReadAllText($p,[Text.Encoding]::UTF8), (New-Object Text.UTF8Encoding($true)))`
- 出中文用 `.NET`：`[System.Text.Encoding]::GetEncoding(936)` / `UTF8Encoding($true)`（带 BOM，给 Inno 的 .iss 与 C# 源码）。

### 3.6 体积与压缩实验
| 形态 | 展开 | 压缩后 | 说明 |
| --- | --- | --- | --- |
| 精简负载（框架依赖） | 0.7 MB | **0.4 MB** | 目标机已装 .NET 8 桌面运行时时用（安装时自动探测） |
| 自包含负载（**当前方案**） | 146 MB | **61.9 MB** | `dotnet publish /p:SelfContained=true` 真自带运行时（deflate，解压快） |
| 旧的"假内置运行时" | 157.8 MB | 65.8 MB | 平铺复制 shared 目录、没有 hostfxr、runtimeconfig 是 `frameworks` → 实际走系统 .NET（已废弃） |
| LZMA 变体（已回滚） | — | 46.9 MB | Python `lzma` + 系统 `tar`，省 19 MB 但解压慢，源码留在 `安装器\Installer-lzma.cs` |
| 单文件安装包 | — | **62.7 MB** | = stub + wizard.zip(0.4) + slim(0.4) + full(61.9) + 32B footer |

- 换自包含发布后**包体反而小了 4 MB**（66.7 → 62.7 MB），因为不再复制用不上的卫星资源与重复文件。
- AspNetCore 的运行时包在自包含还原时会被 SDK 无脑请求（`NU1101`），已用 `Directory.Build.targets` 摘掉，见 §6.2。

### 3.7 工作目录清理：锁文件协议（**本轮核心修复**，别再退回老写法）
问题：向导就在 `lb-setup` 里运行，它没退出前这个目录删不掉（exe/dll 被占用）；老写法 `WaitForExit()` 又会让
解包器**一直挂在后台**（用户不关向导就永远挂着），而且删除常失败 → 用户抱怨"卡运行 + 留下 225MB 垃圾"。

现在的做法（三半，缺一不可）：
1. **向导**（`WorkDirLock.cs`）：如果自己是从名叫 `lb-setup` 的目录里跑起来的，就在**父目录**独占打开
   `lb-setup-running.lock`（`FileShare.None`）并一直按住；进程一退出，句柄自动释放。
2. **解包器**：启动向导后立刻退出，留下一个纯 ASCII 的 `lb-setup-清理.cmd`：
   ① 等锁文件**出现**（最多 60 秒，没出现＝向导根本没起来）→ ② 等它**能删掉**（＝向导已退出，最多约 10 分钟）
   → ③ `rd /s /q` 工作目录（最多 12 次重试）→ ④ 自删。向导真卡住就不删，留给"下次运行安装包先清旧目录"兜底。
3. **解包器还会做两件"避免撞锁"的事**（本轮补的，用户实测踩到过）：
   - 启动前先看锁文件**能不能独占打开**：不能＝向导还在跑 → 把它的窗口 `ShowWindow+SetForegroundWindow`
     叫到前台就退出，**绝不再解压**（旧版会硬解 → 报"文件正由另一进程使用"）。
   - 工作目录里放 `lb-setup-ready.txt`（mode + 四段长度）：内容与当前一致且关键文件都在 → **跳过解压**，
     第二遍双击安装包就是秒开。

**为什么不用 `tasklist` 判断向导在不在**：本机实测 `tasklist /fi "PID eq N"` 会返回 `ERROR: Access denied`，
一旦匹配不到就会被误判成"向导已退出"→ 提前删目录 → 向导正在用的 DLL 被删掉直接崩。能不能删掉锁文件是骗不了人的。
（`UninstallPlan.BuildScript()` 里卸载脚本同理：靠"卸得掉卸载器自己的 exe 没有"判断，不用 tasklist。）

**清理脚本正文一律纯 ASCII、中文路径全部当参数传**：cmd 按系统代码页读 `.cmd` 文件字节，中文写进文件容易乱码
（§3.5 的坑）；命令行参数是 Unicode 转过来的，不会乱。传参形式：`cmd.exe /c ""脚本" "参数1""`（外层那对引号是必须的）。

**三步界面**：路径页 → 安装中（可取消）→ 完成页。头部（应用名/图标/按钮）**三态常驻**。

| 元素 | 规格 |

**卸载器**（`卸载记账本.exe` = 向导 exe 的副本）：
- **进入卸载流程的两种方式**：① 参数 `/uninstall`、`--uninstall`、`-uninstall`、`/u`；② **exe 文件名以「卸载」开头**
  （`Program.IsUninstallInvocation`）—— 双击 `卸载记账本.exe` 必须走卸载，而不是又开一遍安装向导。
- 流程：确认框 → 删桌面/开始菜单快捷方式 → 删注册表 `HKCU\...\Uninstall\记账本` → `taskkill /f /im 记账本.exe`
  并**等它真的退出**（最多 6 秒轮询）→ **删程序文件但保留 `数据/配置/导出/备份`**（`UninstallPlan.RemoveProgramFiles`，
  跳过正在运行的自己）→ 弹"卸载完成"（写清数据留在哪）→ 写脚本（**放安装目录外面**，不写 `%TEMP%`）→ `cmd /c` 起脚本 → 退出。
- 清理脚本（`UninstallPlan.BuildScript`，纯 ASCII）：`cd /d %SystemRoot%`（**必须**，否则删不掉自己所在的目录）→
  `del` 安装目录里的剩余文件（主要是卸载器自己的 exe，被占用就重试 20 次×~3 秒）→ **`rd`（不带 `/s`，只删空目录）** → 自删。
- **数据安全硬规则**：脚本只用不带 `/s` 的 `rd`，所以**即使脚本出了任何意外，也绝不可能删掉 `数据/配置/导出/备份`**
  ——有数据目录在，`rd` 必然失败，数据原地不动。安装目录里只要还有账本数据，卸载后那个文件夹就会留着（**这是用户 2026-10-09 拍板的**：宁留文件夹，不丢账本）。
- 危险目标（盘根 `D:\`、用户目录、`Program Files`、`Windows` 等，`UninstallPlan.IsUnsafeToDelete`）**不自动删**，只提示用户手动处理。

## 5. 应用本体的近期修复与设计规范

### 5.1 近期修复（**必看**）
1. **关闭主窗口必须退出程序**：`Program.Main` 里 `ShutdownMode` 由 ~~`OnExplicitShutdown`~~ 改为 **`OnMainWindowClose`**。
   （`OnExplicitShutdown` 是做截图自动化时留下的，会导致关窗口后**进程残留后台**，同时连带让"卸载删不掉目录"。）
2. **单实例检查**：`Mutex(true, @"Local\LedgerBook-记账本", out isFirst)`；已在运行 → `ShowWindow(SW_RESTORE)` + `SetForegroundWindow` 调出原窗口；调不动才提示。
3. **负载取用不写 `%TEMP%`**（向导）：优先用 exe 旁边的 `payload-*.zip`；仅当内嵌资源时才写"旁边"的 `.tmp`。
4. 解包器/向导/卸载器脚本**不用 `%TEMP%`**。
5. **证书脚本不再写 `%TEMP%`（本轮）**：以前是写 `%TEMP%\ajmn-信任证书.ps1` 再 `-File` 跑，
   而本机 `%TEMP%` 被安全策略锁住 → **勾了"信任签名证书"必然失败**（用户从没成功过）。
   现在改成 `powershell -EncodedCommand`（UTF-16 base64，**不落任何临时文件**），`.cer` 也改放安装目录，导完即删。
6. **卸载器认文件名（本轮）**：上一轮文档说 `-新.exe` 里已修，但**源码里当时并没有这段**（`Main` 只认 `/uninstall`），
   双击 `卸载记账本.exe` 会打开安装向导。本轮真正落地：`/uninstall`、`--uninstall`、`-uninstall`、`/u` 或文件名以「卸载」开头。
7. **解包器不再等向导（本轮）**：见 §3.7（立即退出 + 锁文件 + 独立延迟清理脚本）。
8. **卸载后目录删不掉（本轮）**：老脚本 `rd /s /q` 加"安装目录里跑着的自己"，注定删不掉；且老脚本把数据一起删了却提示"数据保留"。
   现在：C# 先删程序文件（留数据目录）→ 弹提示 → 脚本从**目录外**启动、先 `cd /d %SystemRoot%`、只 `rd` 空目录。见 §4。

### 6.2 环境陷阱（**这些坑让我绕了很多小时，务必遵守**）
1. **我的进程带沙箱**（只允许写 `D:\desktop\记账\...`）→ **我启动的任何 GUI 都继承该限制** ✗
   ⇒ 曾据此误判"安装到 D:\记账本 / 桌面全被拒" —— 那是**测量假象**，用户自己双击是正确的。
   ⇒ **不要用 `Start-Process` 启动安装器来替用户验证**；只做文件级/日志级验证。
2. **我的 `$env:TEMP` 被重定向**（`...\Temp\dsh-XXXX`）→ 不能据此判断用户的 `%TEMP%` 是否可用；要读**绝对路径** `C:\Users\ajmnl\AppData\Local\Temp`。
3. 打包/覆盖前**先结束残留进程**（`记账本`、`lbsetup`、`记账本-安装包*`、`wextract`），否则文件被锁 → 只能另存 `-新` 后缀。
4. `Start-Process` / `Start-Job` / `cmd /c` 包装在本环境多次挂死 → **直接用 `& exe ... | Select-Object -Last N`**；GUI 自动化用程序自带的 `--screenshot/--shot` 参数。
5. 沙箱里**创建证书/读 Defender 设置会被拒**（`NTE_PERM` / 拒绝访问）→ 这类事只能让用户做或放到安装时做。
6. **本环境的 shell 是 Windows PowerShell 5.1**（`$PSVersionTable.PSEdition = Desktop`）：
   - 带中文注释的 `.ps1` **必须存成 UTF-8 带 BOM**，否则按系统代码页(GBK)读 → 满屏乱码 + 语法错误
     （本轮踩过：用 `edit` 工具改过 `.ps1` 后 BOM 会掉，改完记得补 BOM）。
   - `Get-Content` 读**无 BOM 的 UTF-8 中文文件**同样会乱码（`Directory.Build.props` 就被读坏过，
     导致 `[xml]` 解析报"开始标记 Product 与结束标记 PropertyGroup 不匹配"）→ 用
     `[System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)` 或 `Get-Content -Encoding UTF8`。
7. **`ShellExecuteEx`（`UseShellExecute = true`）在本沙箱里会挂死** —— 解包器启动向导那一步正好用它
   （产品必须保留 `true`，否则带 `requireAdministrator` 的向导起不来、弹不出 UAC）。
   ⇒ 想在本环境端到端跑解包器，就编一个 `UseShellExecute = false` 的**测试变体**（`安装包自检.ps1` 已经这么做）。
   ⇒ 同理：不要在沙箱里 `Start-Process` 启动 setup.exe，会一直挂着并留下 GUI 进程（父 job 结束时才被杀掉）。
8. **`tasklist /fi` 在本环境会被拒**（`ERROR: Access denied`）→ 别用枚举进程判断"某进程还在不在"，
   用**文件锁**（能删掉＝已退出），见 §3.7。
9. **解包器是 C# 5**（系统自带 `csc.exe`）：不能用 `=>` 表达式体、`$"..."` 插值、`?.`、`out var`、file-scoped namespace。
   本轮栽过两次（`LockPath(...) => ...`、`namespace X;`），编译报的错还很含糊（`CS1519 / CS1514`）。
10. **本机 `dotnet` 连不上 nuget.org**（`NU1301: Unable to load the service index`；TCP 443 能连、TLS/HTTP 被切断，
    疑似安全软件只拦 dotnet 进程）→ 自包含发布必须**离线还原**：手动下 runtime pack 的 `.nupkg` 放进
    `临时\nuget-离线\`，用 `临时\NuGet-离线.Config`（`<clear/>` + 本地文件夹源）。**版本要和工具链里的运行时版本一致**
    （当前 8.0.31，用 `dotnet --list-runtimes` 或 `LB-构建工具链\dotnet\shared\Microsoft.NETCore.App` 目录名确认）。
11. **自包含还原会被 SDK 无脑要求 `Microsoft.AspNetCore.App.Runtime.win-x64`**（连空白控制台工程都这样）→
    用 `LB-v2.0\Directory.Build.targets` 里的 `<KnownFrameworkReference Remove="Microsoft.AspNetCore.App" />` 摘掉。
    附带坑：**XML 注释里不能出现两个连续减号**，写命令行参数时绕开（否则 MSBuild 报 `MSB4024` 加载失败）。
    另一个低级但致命的混淆：**应用版本（2.0.1）≠ 运行时版本（8.0.31）**，离线包名按前者去找必然找不到。
12. **自包含产物长什么样**（判定"真自带运行时"）：`hostfxr.dll` + `hostpolicy.dll` + `coreclr.dll` +
  `记账本.deps.json`（含 `Microsoft.*.App.Runtime.win-x64/8.0.31` 资产）+ `runtimeconfig.json` 里 `includedFrameworks`；
  跑起来 trace 会打印 `Executing as a self-contained app as per config file`。
  只把 `shared\` 平铺复制进目录**不算**自带运行时（那正是本轮的旧 bug）。
13. **这台机器禁止写 `HKCU\...\Uninstall` 分支**（实测：连新建一个测试键都报"访问被拒绝"，而键的 ACL 写着
  `ajmnl 完全控制` → 是安全软件/策略在拦；疑似与"未签名程序写入拦截"同源）。
  ⇒ **任何"登记卸载信息"都必须是非致命步骤**：写不进去只影响"应用和功能"里能不能看到，
  结果要如实写进 `安装信息.txt` 和完成页，并在开始菜单额外放一个「卸载记账本」快捷方式兜底。
  ⇒ 同理，别把"能不能写注册表/能不能建快捷方式"当成安装成功的判定条件。
14. **判定"某进程还在不在"别用 tasklist / 别用 WaitForExit 长等**（本轮踩的坑）：
  - `tasklist /fi` 在本环境会被拒（见第 8 条）；
  - "向导刚起来就崩了"要用**短宽限**判断（给 3 秒，看 `HasExited` + `ExitCode != 0`），
    写成 `WaitForExit(15000)` 会让解包器白等 15 秒（用户会以为卡住）。
15. **打包脚本自己也要自检**：本轮 `工具\组装安装包.py` 一度**漏写 stub**（拼出来的"安装包"根本不是 exe），
  是靠"解包器端到端测试真跑一遍"（WinError 216 / 开头不是 MZ）抓出来的 ——
  所以 `组装安装包.py` 现在会自己检查开头是不是 `MZ`，`校验安装包.py` 也会核对 stub 长度。
16. **`robocopy` 默认不递归**（甲方案踩的坑，代价是一次"程序说找不到框架"的误诊）：
   要复制整棵目录树必须显式加 `/E`。证据：`robocopy src dst` 之后 `dst\sub\b.txt` 不存在，加 `/E` 才有。
   ⇒ 本项目里复制运行时/负载一律写 `/E`；`打包-自研安装包.ps1` 的注释里也留了这句话。
17. **甲方案的运行时布局是"私有运行时"**（`hostfxr.dll` + `shared\Microsoft.*\<版本>\`，`runtimeconfig.json` 仍是 `frameworks`）：
   - 好处：**同一份程序负载两种机器通用**（有 .NET 就用系统的，没 .NET 就用包内的），所以"更新只写 0.4MB"成立；
   - 判定用 trace：`Chose FX version [<安装目录>\shared\Microsoft.WindowsDesktop.App\8.0.31]` 才是走包内；
     如果看到 `Executing as a self-contained app` 那是旧的"平铺自包含"布局（已弃用）。
   - **别再**把 `shared\` 平铺进目录（那正是老 bug），也别把语言卫星包全带上（13 种语言 +204 文件 +10MB，
     只留 `zh-Hans`；名字用显式清单删最稳，靠 `$dir.Parent.Name -match '^\d+\.\d+\.\d+$'` 判会**一个都删不掉**）。
18. **安装器会清理"本版清单之外"的文件**（设计如此：免得旧版本残留堆在安装目录里）：
   清单 = 程序负载 + 运行时负载（含清单资源 `runtime-files.txt`）+ 卸载器/安装信息/证书；
   `数据/配置/导出/备份` 目录永不碰。⇒ **别把重要文件丢在安装目录里**，也别写"文件数不变"这类断言（测试脚本自己留下的
   trace/截图会被清掉，我第一版自检就是这么误报的）。
19. **小包（不含运行时负载）必须能保护已装的运行时**：曾经"跳过运行时"的那次更新把运行时当残留删了
   （症状：更新后程序起不来）。修法 = 随包带 `runtime-files.txt` 清单 + 兜底规则（`hostfxr.dll`/`hostpolicy.dll`/
   `运行时版本.txt`/当前版本 `shared\...` 一律不删），并**把它写成自检里的回归项**。
20. **PowerShell 函数的返回值会连带管道输出**：`$p.WaitForExit(...)` 不加 `| Out-Null` / `$null =` 会把
   `True` 和 `ExitCode` 一起返回 → `$code` 变数组 → 后续 `-eq 0` 变数组比较 → 报"无法把 Object[] 转成 Boolean"。
   本轮自检脚本踩过一次。
