# 记账程序 · 设计文档 v3

> 确认结果：桌面小窗口（tkinter）+ 每日 TSV 纯文本 + 月度汇总 CSV + 导入导出闭环 + 支持编辑/删除任意历史记录（**不设**「撤销上一笔」，删除即撤销）+ 每日文件写入稳定编号列（**不再重复存日期列**，控制文件体积）。

---

## 1. 总体思路

- **每日文件是唯一数据源**，程序只做三件事：读每日文件 → 展示/统计 → 写回每日文件。
- 月度汇总、导出文件都是**可重建的衍生品**，删掉不影响数据。
- 配置与数据分离，分类、支付方式可自行增删，无需改代码。
- 不依赖任何第三方库，只用 Python 标准库（tkinter / csv / decimal / json / datetime / shutil），双击即可运行。

## 2. 界面设计（单窗口 + 多标签页）

```
┌─ 记账本 ──────────────────────────────────────────────┐
│ [记一笔] [查询统计] [月度汇总] [导入/导出] [设置]      │
├───────────────────────────────────────────────────────┤
│  （各标签页内容）                                      │
├───────────────────────────────────────────────────────┤
│ 状态栏：数据目录 D:\desktop\记账\数据 ｜ 本月 12 笔     │
└───────────────────────────────────────────────────────┘
```

### 2.1 记一笔

| 控件 | 说明 |
| --- | --- |
| 日期 | 默认今天，可补记历史日期（年、月、日三个输入框） |
| 类型 | 支出 / 收入 单选，默认支出 |
| 金额 | 输入框，`Decimal` 校验，必须 > 0，最多两位小数 |
| 分类 | 下拉框，来自 `配置\分类.json`，随类型切换列表 |
| 支付方式 | 可编辑下拉框，来自配置，默认取设置里的默认值 |
| 备注 | 单行文本，可空 |

按钮：`保存并继续`（清空金额/备注，焦点回到金额，便于连续记账）、`保存并关闭`。
保存成功后状态栏提示：`已记入 2026-02-14 09:12：支出 餐饮 ¥18.50（微信）`。

**没有「撤销上一笔」按钮**：它与「删除任意历史记录」是同一件事，两条入口只会让人犹豫。记错了就切到「查询统计」，双击该行改掉，或选中后删除。程序内部也只有一套删除逻辑。

### 2.2 查询统计

- 条件区：起始日期、结束日期 + 快捷按钮（今天 / 昨天 / 本周 / 本月 / 上月 / 今年 / 全部）、类型（全部/支出/收入）、分类（全部/具体）、关键词（匹配备注与分类）。
- **类型与细分联动（硬规则）**：类型一改（支出 ⇄ 收入 ⇄ 全部），细分**立刻回到「全部」**并按新类型重列选项；
  选「收入」时细分里根本不会出现支出种类。否则会出现「收入 + 交通」这种永远查不到东西的组合。
  细分下拉也做了兜底：当前选中的种类如果不在新选项里（例如刚被删掉），同样回到「全部」。
- 明细表（Treeview，可按列排序）：日期、时间、类型、分类、金额、支付方式、备注。**不显示编号**。
- **响应式**：明细与分类统计并排（左半 / 右半）；容器宽度 < 900 时自动改成上下排列。
  「快捷范围」「筛选条件」「操作按钮」这些成排的控件会自动回车换行，任何窗口宽度下都不裁内容。
- **明细列宽自适应**：宽窗口下「备注」吃掉多余空间；窗口变窄时先压「备注」，再按比例压其它列，
  但每列不低于可读下限 —— 保证「日期 / 时间 / 类型 / 分类 / 金额 / 支付方式 / 备注」表头始终一行放得下。
- 汇总区：`收入合计 / 支出合计 / 结余 / 笔数`（单独占一行，窄窗口也不会和按钮挤在一起）。
- **分类统计（右半区）可以选多种视图**，在「设置 → 查询 → 分类统计里显示哪些视图」里多选：
  `表格 / 饼状图 / 柱状图 / 方格图`，默认「表格 + 饼状图」。
  - 多个视图按「接近正方形」自动分配区域：1 个占满、2 个并排、3~4 个 2×2、更多按 3 列排；
  - **只画有权重的分类**：占比不足 **0.05%**（换算出来就是 0.0%）的分类不画进图里，
    否则图例会被一堆看不出权重的项挤乱；被挡掉的项会在图下用一行小字说明
    「另有 N 项占比不足 0.05%，未在图中显示」，**表格视图仍然列出全部**，信息不会丢；
  - **饼状图（3D）**：压扁成椭圆，先画一份向下偏移的深色扇区当「厚度」，再把顶面盖上去，
    看起来就是立体的；面板够宽时饼在左、图例在右（图例能一次列全）；
  - **柱状图（横向 3D）**：每项一条横向的「厚板」——正面用原色、顶面变亮、右侧面变暗，
    行高随面板高度自动放大并竖直居中；数值与占比标在右侧；
  - **方格图**：10×10 共 100 个方格，**1 个方格 = 1%**，用最大余数法保证正好填满 100 格；
    方格边长按可用区域算、受 46px 上限约束并居中，下面标注「每个方格 = 1%（共 N 格有色，M 格空）」；
  - 三个图形都是**用 tkinter.Canvas 手绘**（`ledger/ui/charts.py`），不引入任何第三方绘图库，
    打包体积不变；图例按可用高度自动截断并在末尾写「…… 还有 N 项」，不会画到面板外。
- 分类统计表格的列宽也会自适应（和明细一样有可读下限），小面板里不会把「金额 / 占比」挤掉。
- 分类小计表：类型、分类、笔数、金额、占比（按金额降序）。
- 按钮：`查询`、`编辑选中`（双击行同样触发）、`删除选中`（支持多选）、`导出结果 CSV`。

### 2.3 月度汇总

- 选择月份 → `生成汇总`，展示两张表：按日汇总、分类小计。
- `导出月度汇总 CSV` → 写入该月目录下 `_月度汇总.csv` 与 `_分类小计.csv`；不导出时也能在界面看。
- 汇总始终由每日文件重新计算并覆盖写入，不读取旧汇总。

### 2.4 导入 / 导出（在设置页的「导入 / 导出」页里，不再是独立标签页）

**导出**

```
导出
  导出路径为 D:\...\导出            [ 打开导出目录 ]
  导出范围   从 [ 2026-09-08 ] 到 [ 2026-10-08 ]   [ 导出 ]
  点日期会弹出万年历，从当前这天开始选；这次导出 … 共 31 天。
```

- 第一行就是「导出路径为 …」，**点这行文字可以直接选目录**（蓝色带下划线，悬停提示
  「点击可以选择导出到哪个文件夹」），选完写进设置项 `导出目录`（留空 = 程序目录下的 `导出\`）；
  右侧保留「打开导出目录」按钮；
- **导出范围**：从（默认**上月同日**）到（默认**今天**），两个日期点开都是**万年历**，
  打开时停在当前选的那天所在的月份、那天高亮；能翻月、有「今天」按钮；
  起始晚于结束会自动对调并提示；
- 导出文件名：`导出_起始_结束_时分秒.csv`，写到上面的导出目录里；
- 「查询统计」页的「导出结果 CSV」保留：它导出的是**当前筛选结果**（类型/分类/关键词），
  和这里的按日期范围导出不是同一件事。

**导入**

- 只有一张预览表：能导入的行和**读不出来的行放在一起**，用「状态」列区分
  （`可导入` / `读不出来：原因`），不再分成两张表；
- **冲突策略不再重复放选项**：只有设置项 `导入默认策略` 一份，导入区只显示当前用的是哪个
  （「冲突策略：跳过重复（在上面的设置里改，这里不重复放选项）」）；
- 「自动新增配置里没有的种类」勾选框保留（这是每次导入的临时决定，不是重复配置）；
- 导入前自动备份受影响月份；完成后给出「成功 / 跳过 / 覆盖 / 失败」报告；
  「导出读不出来的行 CSV」会把失败行连同**原始内容**一起导出（错误清单含 行号 / 原因 / 内容）。

两种格式的共用细节：

- 导出写 CSV，带「日期」列（由编号还原），UTF-8 带 BOM，Excel 双击不乱码；
- 导入自动识别编码（UTF-8 / GBK / UTF-16）、分隔符（Tab / 逗号）与列名（中英文都认）；
  缺列时明确报出缺哪一列；
- 日期来源优先级：`日期` 列 > 编号前 8 位 > 文件名里的 `YYYY-MM-DD`；
- 逐行校验：日期、类型必须是支出/收入、金额必须为正；
- 三种冲突策略（由设置项 `导入默认策略` 决定）：
  1. **跳过重复**（默认）：编号相同，或（时间+类型+分类+金额+支付方式+备注）完全一致；
  2. **按编号覆盖**：同编号记录用导入值替换；
  3. **全部追加**：忽略原编号，重新分配当日编号；
- 由此形成闭环：导出的 CSV 可原样导回，Excel 里批量整理后也能导回。

### 2.5 设置区（低频开关的统一去处）

**约定（后续版本请遵守）**：主线三页（记一笔 / 查询统计 / 月度汇总）只放日常操作；
凡是「平时用不到、但某个时候需要调」的东西，一律进设置区，不要往主线页面加按钮或开关——
既避免误触，也避免界面越来越挤。

设置区是**声明式**的：每个设置项在 `ledger/config.py` 的 `SETTING_SPECS` 里声明一次
（键名、分组、类型、默认值、说明、可选项来源），设置页会自动生成对应控件、自动持久化到
`配置\设置.json`，`selftest.py` 也会自动覆盖到它。**新增一个设置项 = 加一行声明 + 在用到它的地方
`config.get("键名")`**，界面不用改。

当前设置项：

| 分组 | 设置项 | 类型 | 默认 | 作用 |
| --- | --- | --- | --- | --- |
| 通用 | 货币符号 | 文本 | ¥ | 金额前面显示的符号 |
| 记一笔 | 默认类型 | 选项 | 支出 | 打开「记一笔」时预选 |
| 记一笔 | 默认支付方式 | 选项 | 微信 | 记一笔时预选；选项来自支付方式列表 |
| 记一笔 | 保存后自动清空金额与备注 | 开关 | 开 | 关掉便于连记同金额（金额会被全选） |
| 记一笔 | 显示「本次打开后已记」列表 | 开关 | 开 | 关掉让录入区更简洁 |
| 查询 | 打开查询页时的默认范围 | 选项 | 本月 | 今天 / 本周 / 本月 / 上月 / 今年 / 全部 … |
| 查询 | 明细最多显示行数 | 整数 | 500 | 0 表示不限；合计永远按全部记录算 |
| 查询 | 分类统计里显示哪些视图 | 多选 | 表格、饼状图 | 可多选 表格 / 饼状图 / 柱状图 / 方格图；**改完点「保存」才生效**，多个视图自动分配区域 |
| 导入 / 导出 | 导入时默认的冲突策略 | 选项 | 跳过重复 | 导入区只显示它，不再重复放一遍选项 |
| 导入 / 导出 | 导出目录 | 文本 | 空 | 空 = 程序目录下的 `导出\`；在导出区点路径也能改 |
| 数据与备份 | 改 / 删 / 导入前自动备份 | 开关 | 开 | 关掉省空间，但改错了找不回来 |
| 数据与备份 | 备份目录 | 文本 | 空 | 空 = 程序目录下的 `备份\`；在数据与备份页点路径也能改 |

设置区里还放着：

**分页布局**：设置区顶部是「设置」大标题 + 「恢复全部默认」，下面一条**扁平分页标签**
（当前页加粗 + 红色粗下划线），一屏只显示当前页，其余页完全不占地方 —— 这就是「方便寻找 + 减少冗余」的做法。
页签顺序：`通用 → 记一笔 → 查询 → 种类与支付方式 → 导入 / 导出 → 数据与备份 → 关于`。
其中前五个名字与 `SETTING_SPECS` 里的「分组」一致：**声明一个新设置项时，它的分组名就是它所在的页**，
不需要改界面代码；`种类与支付方式`、`关于` 这两页是纯界面页。

- **种类与支付方式**页（收入种类 / 支出种类 / 支付方式，三者排版一致）：

  ```
  收入种类   ┌───────────────┐
             │ ⣿ 工资        │   [ 修改 ]
             │ ⣿ 奖金        │
             │ ⣿ 兼职        │
             └───────────────┘
  支出种类   ┌───────────────┐
             │ ⣿ 餐饮        │   [ 修改 ]
             └───────────────┘
  支付方式   ┌───────────────┐
             │ ⣿ 微信        │   [ 修改 ]
             └───────────────┘
  ```

  - **明显边框 + 完整显示**：方框是白底 + 1px 灰边框（像输入框），高度按内容自动撑开，
    **所有选项一次性全显示、不会被截断**（`max_rows=None`，超过 20 项才退回内部滚动）；
    宽度也按最长的那一项自动撑开，长名字不会被切。
  - **拖动排序**：每行最左边一个「小横线」手柄，按住上下拖，松手立即整体保存；
    鼠标在手柄上停留约 0.45 秒弹出深色气泡「拖动可以调整顺序」。
  - **修改按钮**：打开编辑窗口，可新增 / 改名（双击也行）/ 删除 / 上移 / 下移（与拖动共用同一套排序逻辑）。
    列表顺序会被保留——**顺序就是记账页下拉框的顺序**，所以常用的可以往前挪。
  - 删掉某一项不影响已经记过的账，只是以后下拉框里不再出现它。
- **数据与备份**页：

  ```
  自动备份   [✓] 改 / 删 / 导入前自动备份
  ── 数据与目录 ──
  数据目录为  D:\...\数据                 [ 打开数据目录 ]
  备份路径为  D:\...\备份                 [ 打开备份目录 ]      ← 点路径可改
  配置目录固定跟着程序走：D:\...\配置
  ── 配置数据 ──
  把「设置和种类」打包成一个文件……
  [ 导出配置数据 ]  [ 导入配置数据 ]
  ```

  - **备份路径与导出路径完全一致的做法**：可点选的蓝色路径（悬停提示「点击可以选择备份到哪个文件夹」），
    写进设置项 `备份目录`（留空 = 程序目录下的 `备份\`），右侧保留「打开备份目录」；
    改完之后「改 / 删 / 导入前」的快照都会落到新目录；
  - **配置数据导出 / 导入**：把「设置 + 种类」打包成一个 JSON 文件（`配置_时间_时分秒.json`，
    带 `类型：记账本配置` 标记，默认写到导出目录），换电脑、重装或想回退时用；
    导入是**两段式**：先预览（只读，显示「设置 N 项，支出 x 个、收入 y 个」），
    确认后才覆盖，而且**覆盖前会把现有的 设置.json / 分类.json 备份到 `<备份目录>\配置\时间戳\`**；
    不是配置包的文件会被明确拒绝并说明原因。
- **关于**页：程序版本、数据格式版本、设置版本、数据目录、设置项数量、自测方法。

实现上是 `ledger/ui/common.py` 里的 `SortableList`（自绘行 + 手柄 + 拖动重排 + 边框 + 自适应大小）、
`Tooltip`（悬浮提示）、`FlatTabs`（分页标签条）、`ItemListDialog`（通用列表编辑窗口，
`CategoryDialog` 是它的专用壳），后续有类似需求直接复用。

行为约定：

- **保存即生效**：改完立刻作用到各页，不需要重启（由 `App.apply_settings_changed()` 分发，
  各页实现 `apply_settings()`）；
- **一定有默认值**：删掉 `配置\设置.json` 也能正常跑；值类型不对或填了非法值会自动回落到默认值；
- **可一键还原**：设置区顶部「恢复全部默认」，只重置偏好，不动 `分类.json`、不动任何账目；
- **不碰规则**：金额精度、编号规则、去重键、文件格式这类**不允许**做成开关，
  不能让「配置」改变账目的含义。

## 3. 数据文件结构

```
D:\desktop\记账\
├─ 记账.bat                       # 双击启动（纯 ASCII + CRLF，原因见第 8 节）
├─ run.py                         # ASCII 名字的启动入口，供 .bat 调用
├─ 记账.py                        # 入口：开窗口 / api 命令行 / 自测
├─ 打包exe.bat                    # 双击即可打包成 dist\记账本.exe（纯 ASCII）
├─ build.spec                     # PyInstaller 打包配置（exe 的中文名写在这里面）
├─ selftest.py                    # 不弹窗自检（python 记账.py 自测）
├─ 设计文档.md
├─ 使用说明.md
├─ ledger\                        # 程序代码包
│   ├─ __init__.py
│   ├─ paths.py                   # 目录/路径规则，缺目录自动创建、不依赖工作目录
│   ├─ table.py                   # 表格读写：编码与分隔符嗅探、原子写
│   ├─ model.py                   # 记录模型、编号规则、金额/日期解析（格式契约）
│   ├─ config.py                  # 分类.json、设置.json 读写
│   ├─ storage.py                 # 每日文件读写、编号分配、改删、备份、单实例锁
│   ├─ query.py                   # 查询与统计（含「今天/本月/上月…」快捷范围）
│   ├─ summary.py                 # 月度汇总生成
│   ├─ transfer.py                # 导入 / 导出与冲突处理
│   ├─ api.py                     # 接口门面：JSON 进、JSON 出（界面与外部程序共用）
│   ├─ cli.py                     # 命令行：api <命令> '<json>'
│   └─ ui\                        # 界面层，只调用 api.py，不含业务规则
│       ├─ app.py                 # 主窗口与标签页装配（顶层只有 4 个标签页）
│       ├─ common.py              # 日期框/万年历、可拖排序列表、悬浮提示、分页标签条、通用列表编辑窗口
│       ├─ record_tab.py
```

### 3.1 每日流水文件 `数据\YYYY\MM\YYYY-MM-DD.tsv`

UTF-8 BOM，Tab 分隔，首行表头，一行一笔，共 7 列：

```
编号	时间	类型	分类	金额	支付方式	备注
20260214-001	09:12	支出	餐饮	18.50	微信	早餐
20260214-002	12:40	支出	交通	4.00	支付宝	地铁
20260214-003	20:05	收入	工资	8500.00	银行卡	2 月工资
```

约定：

- **编号**：`YYYYMMDD-NNN`，当日内三位递增；删除不回收号，新增取当日最大号 +1（超过 999 自动扩展位数）。
- **不存日期列**：编号前 8 位即日期，文件名也带日期，重复存一列纯属浪费体积；一行因此只多约 14 字节。导出 CSV 时按编号还原出「日期」列。
- **类型**只能是 `支出` 或 `收入`；**金额永远存正数**，正负由类型决定，避免符号混乱。
- **金额**用十进制字符串保存、固定两位小数，不用浮点数运算；`0.00` 不允许录入。
- 时间格式 `HH:MM`；日期格式 `YYYY-MM-DD`。
- 文件缺失时自动创建并写表头；表头缺失或列顺序不同时按列名兼容读取。
- 写入采用「临时文件 + 原子替换」（`os.replace`），避免中途崩溃损坏数据。

## 4. 关键行为约定

- **响应式布局约定（所有页面通用）**：
  - 窗口最小尺寸 **620 × 520** —— 这个宽度刚好能让「明细」表头一行显示完；最大尺寸 2600 × 1700；
  - 凡是「一排控件」（快捷范围按钮、筛选条件、操作按钮、月度汇总工具条、设置项、状态栏…）
    都用 `common.WrapRow` 排版：**一行放不下就自动回车换到下一行**，窗口再窄也不裁掉内容；
  - 查询页左右分栏：容器宽 ≥ 900 时「明细 | 分类统计」并排，< 900 时改成上下排列（明细在上）；
  - 表格类（明细、分类统计、导入预览）保留自己的滚动条，不强行塞进一屏。
- **外观约定（圆角）**：
  - **按钮全部自绘圆角**：ttk 的主题（vista/clam）画不出圆角，所以 `common.RoundedButton`
    用 `tk.Canvas` 自绘「按 1/4 圆弧取点的圆角矩形 + 居中文字」，带悬停 / 按下 / 禁用三种状态；
    圆角半径 7~9px，主操作（保存 / 查询 / 生成汇总 / 确定 / 执行导入…）用主色，其余用中性色。
    它兼容 `ttk.Button` 的常用接口（`cget("text")`、`configure(text=…)`、`state(["disabled"])`、`invoke()`），
    所以调用处和自测都不用改写法；界面上**不允许再出现 ttk.Button**（自测会遍历控件树检查）。
  - **窗口圆角**：`common.apply_rounded_window()` 通过 DWM 设置 `DWMWA_WINDOW_CORNER_PREFERENCE`
    （Win11 生效，Win10 / 其它系统静默返回 False，不影响功能）；主窗口和每个弹窗
    （修改记录、种类编辑、万年历）都会调用一次，结果记录在 `App.rounded_corners`。
  - 不引入任何第三方主题库（如 ttkbootstrap），保持零依赖、打包体积不变。
- **拖动窗口的性能约定（硬规则）**：所有跟随尺寸变化的计算都不能逐像素做，必须
  ① **只在变化超过阈值时才算**（`WrapRow.MIN_DELTA = 24`、明细列宽 24、图形 24），
  ② **用 `after()` 防抖**（WrapRow 90ms、列宽 120ms、图形 150ms），松手后统一排一次。
  实测：连续 60 次 1 像素的宽度变化 → **0 次立即重排、1 次防抖重排**。
  界面提供 `flush_pending_layout()` / `flush_pending()`，在切页、保存设置时把挂起的计算立刻做掉。
- **保存即生效，多选例外**：绝大多数设置项改完立刻生效；只有 **`multi`（多选）类型的设置项**
  （目前是「分类统计里显示哪些视图」）旁边带一个「保存」按钮——勾选后按钮点亮，
  点它才写盘并重建面板（这类改动要重画多个图形，不适合每勾一下就生效）。
- **改设置不重读数据**：设置保存后，只有「影响查询的条件」（日期范围、明细行数上限）变化时才重新读文件；
  只换了统计视图或改了别的设置时，**复用上次查询结果直接重画**（`render_from_cache()`），
  自测里有专门的计数断言守着这条（`query_count` 不变、`render_count` 增加）。
- **改别的设置不冲掉当前查询**：只有「查询默认范围」被改动时才重置日期区间，
  改货币符号、统计视图、备份目录等都会保留用户正在看的范围。
- **删掉种类后，记录不改、统计算「其他」（硬规则）**：把某个种类从配置里删掉后，
  已经记过的账**原样留在文件里**（不删记录、不改内容、导出 CSV 也还是原始分类）；
  但在**查询统计与月度汇总**里，这些记录一律并入 `其他`：
  笔数、金额、占比都算到「其他」名下，按「其他」筛选能查到它们；
  把种类再加回配置，它们又自动归回原分类。明细表里会写成 `其他（原 宠物）`，
  既看得出统计口径，也看得出原来是什么，方便回去改。
  实现见 `query.effective_category()`，查询与汇总共用同一份逻辑。
- **编号对用户隐藏（硬规则，后续版本必须保持）**：编号是程序内部的稳定主键（删除不回收、
  导入去重和「按编号覆盖」要用），它只出现在每日 TSV 文件里；**界面上一律不显示**——
  明细表、修改对话框标题、导入预览、删除确认、状态栏提示，都用「日期 + 时间 + 类型 + 分类 + 金额 + 备注」
  来指代一笔记录。导出的 CSV 里保留「编号」列，因为导出的文件要能被原样导回。
  `selftest.py` 里有专门的回归检查（明细表/预览表的列、修改对话框标题、删除确认文案、录入提示）
  守着这条规则，改动界面后跑一次自测即可发现回退。
- **编辑/删除任意历史记录**：在查询结果里选中（可多选删除）→ 二次确认 → 重写当日文件；编号不回收、不重排。
- **写前备份**：编辑、删除、导入前，把受影响月份的每日文件快照到 `备份\YYYY-MM\时间戳\`。
- **并发保护**：启动时在 `数据\记账.lock` 写入进程号；发现锁且进程仍在则提示「程序已在运行」，避免两个窗口互相覆盖。
- **容错读取**：读取时兼容 utf-8-sig / utf-8 / gbk；单行格式异常时跳过并计入状态栏日志，不中断查询。
- **金额计算**：全程 `Decimal`，`ROUND_HALF_UP` 保留两位；只在显示和导出时转字符串。
- **查询性能**：「本月/指定月」只读对应月份目录；「全部/今年」遍历年份目录，命中缓存按文件 mtime 失效。

## 7. 接口契约（给别的程序、别的语言用）

界面层只是 `api.py` 的一个调用方。以后要用别的语言重写界面，有两种方式：

1. **直接复刻数据格式**：`ledger/model.py` 里的列名、编号规则、金额写法就是契约，见 3.1 节；
2. **把本程序当子进程调**：走命令行 JSON 接口，业务规则（校验、编号、去重、汇总）不用重写。

```bat
记账.py api add   "{\"kind\":\"支出\",\"category\":\"餐饮\",\"amount\":\"18.50\",\"note\":\"早餐\"}"
记账.py api query "{\"preset\":\"本月\"}"
记账.py api month "{\"year\":2026,\"month\":2}"
记账.py api list
```

Windows 的 shell 很容易吃掉 JSON 里的双引号，跨语言调用时更稳的两种写法：

```bat
echo {"preset":"本月"} | 记账.py api query --stdin
记账.py api add --file 参数.json
```

约定（详见 `ledger/api.py` 顶部说明）：

- 入参与返回值都是可直接 JSON 序列化的字典；**键名用英文**（跨语言友好），值里的类型仍是数据里的中文「支出/收入」；
- **金额一律字符串**（如 `"18.50"`），避免浮点误差；
- 成功 `{"ok": true, ...}`，失败 `{"ok": false, "error": "人话说明", "error_type": "..."}`；
- 退出码：成功 0，失败 1；输出 UTF-8 JSON。

可用命令：`info`、`init`、`add`、`query`、`update`、`delete`、`month`、`month_export`、
`export`、`export_errors`、`import_preview`、`import_apply`、`days`、`categories`、
`add_category`、`rename_category`、`remove_category`、`save_categories`、
`settings`、`save_settings`、`reset_settings`、`export_config`、`import_config`。

其中 `settings` 会返回 `items`（每个设置项的键名、分组、类型、当前值、默认值、可选项），
外部前端可以直接照着它渲染设置界面；`save_settings` 只改传入的键，未知键会被拒绝。

## 8. 打包 exe 与换语言的准备

已经做好的准备：

- **核心层零界面依赖**：`storage/query/summary/transfer/api` 只 import 标准库，不 import tkinter；
- **路径不依赖当前工作目录**：数据和配置都相对「程序所在目录」推导，打包后用 `sys.executable` 定位；
  想换数据位置（例如放网盘同步目录）只要设环境变量 `JIZHANG_ROOT` 或 `记账本根目录`；
- **数据格式语言中立**：TSV / CSV / JSON，UTF-8（带 BOM 便于 Excel），任何语言都能读写；
- **导入容错**：兼容 UTF-8 / GBK / UTF-16，制表符或逗号分隔，中英文列名；
- **`build.spec` + `打包exe.bat`**：双击即可产出免安装的便携版（首次会自动把 PyInstaller
  下载到工程内，不装进系统）；打包后数据目录（数据/配置/导出/备份）在 exe 同级目录自动创建。

### 8.1 发布结构：所有新产物都在 `LedgerBook\` 里

```
工程根目录\
├─ 记账.py  ledger\  selftest.py  设计文档.md  使用说明.md  build.spec  打包exe.bat   ← 源码，保持原样
└─ LedgerBook\                                  ← 打包产生的一切，删掉不影响源码
    ├─ 记账本\                                   ← 程序本体（onedir）
    │   ├─ 记账本.exe                            ← 双击即用，不依赖 Python
    │   ├─ 记账本-命令行.exe                     ← 同一程序的命令行版（JSON 进 JSON 出）
    │   ├─ _internal\                            ← 运行库（附属文件）
    │   ├─ 使用说明.md  设计文档.md  便携版说明.txt
    │   └─ 数据\ 配置\ 导出\ 备份\               ← 首次运行时自动创建（便携：账目跟着文件夹走）
    ├─ 记账本-便携版-v0.1.0.zip                  ← 安装包：拷到别的电脑解压即用
    ├─ 打包信息.txt                              ← 版本 / 时间 / 校验值 / 怎么重新打包
    ├─ build\                                    ← 构建用的东西，可整个删掉
    │   ├─ .tools\                               ← 下载到本地的 PyInstaller
    │   ├─ work\                                 ← PyInstaller 中间产物
    │   ├─ download_tools.py  release.py         ← 下载工具 / 整理发布
    └─ 版本备份\v0.1.0_<时间戳>\                 ← 打包前的源码快照 + 《回滚说明.txt》
```

- **为什么用 onedir（文件夹）而不是单文件 exe**：单文件版每次启动都要把运行库解压到系统临时目录，
  不少公司电脑和安全软件**禁止往 `%TEMP%` 写可执行文件**，程序会直接起不来（本机沙箱复现了这一点：
  `Failed to extract VCRUNTIME140.dll`）；文件夹模式的 exe 旁边就是运行库，启动更快、不受这类限制，
  发布时压成 zip 一起发即可。
- **为什么构建工具放 `LedgerBook\build\`**：pip 的临时目录在受限环境里写不进去，
  于是 `download_tools.py` 直接下载 wheel（wheel 就是 zip）解压到 `.tools\`，
  全程只写工程目录、可随时删掉、不污染系统 Python。
- **`LedgerBook\build` 是 ASCII 名**：`打包exe.bat` 里不能出现中文（见 8.2），所以构建辅助目录
  和脚本都用 ASCII 名；程序文件夹、安装包、备份目录保留中文名——那些是 Python 创建的，不受代码页影响。

### 8.2 已经踩过的坑（换语言、改启动方式时必须注意）

- **批处理必须「纯 ASCII + CRLF」**：cmd.exe 是按系统代码页读 `.bat` 内容的（中文 Windows 是 GBK），
  文件里的 UTF-8 中文文件名会被解释成乱码，于是报「系统找不到指定的文件」；LF 换行又会让含
  `if (...)` 的分支解析出错。所以 `.bat` 里一个中文都不留，只调用 ASCII 名字的 `run.py`，
  中文路径交给 Python（按 UTF-8 读源码）处理。
- **`.bat` 里不要写中文名文件**：同理，`build.spec` 改成 ASCII 名，exe 的中文名写在 spec 内部
  （那是 Python 读的，不受代码页影响）；构建辅助目录也因此叫 `LedgerBook\build`。
- **单文件 exe 在受限环境会起不来**：PyInstaller onefile 启动时要往 `%TEMP%` 解压运行库，
  沙箱／安全软件一拦就报 `Failed to extract VCRUNTIME140.dll`。所以发布统一用 **onedir** 文件夹模式。
- **改 `build.spec` 里的输出目录要自己建目录**：只改 `CONF["distpath"]/["workpath"]` 的话，
  PyInstaller 不会替你 `makedirs`（它只建自己从命令行解析出来的默认路径），会出现
  `FileNotFoundError: ...\work\base_library.zip`。
- **`pythonw.exe` 可能毫无提示地失效**（某些商店版/受限环境里连 `-c` 都不执行）。当前启动器会先用
  `python.exe` 做一次「能不能 import 界面」的预检，出错时打印真实堆栈并 pause。
  **待办**：再加一层「启动 pythonw 两秒后确认进程还活着，否则自动退回控制台模式」的兜底。

换语言时要保留的只有三件事：① 3.1 节的文件与列格式；② 3.2 节的汇总文件格式；
③ `api.py` 里的校验与编号规则（不回收编号、金额恒为正、去重键 = 时间+类型+分类+金额+支付方式+备注）。

## 9. v2.0 规划（C# / WPF 重写 + 数据格式 v2）

> v0.1.0（Python + Tk 版）已冻结：源码快照在 `LedgerBook\版本备份\v0.1.0-最终_<时间戳>\`，
> 便携包在 `LedgerBook\记账本-便携版-v0.1.0.zip`，冻结时自测 252/252 全绿。

### 9.1 技术选型（定稿）

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 语言 / 界面 | **C# + WPF**，目标框架 **.NET 8（LTS）** | Windows 原生质感；圆角、抗锯齿、DPI 都是系统能力 |
| 目标平台 | **win-x64** | 现有机器和绝大多数目标机器都是 64 位；不做 32 位包 |
| 发布形态 | ① **自包含便携版**（约 60–70MB，双击即用，不装任何东西）② **框架依赖轻量版**（3–5MB，需 .NET 8 桌面运行时） | 兼容「不想装东西」和「想体积小」两类需求 |
| 构建环境 | .NET SDK 装到 `LedgerBook\build\dotnet\`（微软官方**非管理员**安装脚本，不改注册表/PATH） | 不动用户系统，可整个删掉 |
| 安装包 | **Inno Setup**（`LedgerBook\build\innosetup\`），产出单个 `记账本-安装包-v2.0.0.exe` | 安装器要能在**没有 .NET 的电脑**上运行，所以不能用 C#/.NET 写（鸡生蛋）；Inno 生成的是原生程序 |

**体积对照（三个"大小"不是一回事）**

| | 是什么 | 体积 | 在哪 |
| --- | --- | --- | --- |
| .NET SDK | **编译器 + 打包工具**，写程序必须用 | 约 200–300MB | 只在开发机（`LedgerBook\build\dotnet\`），**不进安装包**、不进用户系统 |
| 成品安装包 | 编译好的程序 + 自带运行时（压缩） | 约 60–70MB | 用户下载 |
| 安装后占用 | 解压出来的程序 + DLL | 约 150MB | 用户硬盘（可卸载） |

### 9.2 数据格式 v2（**现在就预留**，读取兼容 v1）

**每日流水 `数据\YYYY\MM\YYYY-MM-DD.tsv`：7 列 → 9 列**

```
编号  时间  类型  分类  金额  支付方式  备注  归属  来源
                                        └预留┘ └预留┘
```

- **归属**：完整用户码（如 `u7k3m9qz4t2p`）；本机记的也写本机用户码，**不留空**（不留「空=本机」的隐含约定）。
- **来源**：设备名（本机首次运行生成如「我的电脑」，设置里可改）。
- 去重键 = `时间+类型+分类+金额+支付方式+备注+归属` → 不同人金额相同的记录**不会**被判重复。
- 旧文件只有 7 列 → 按 v1 读，归属/来源视为「本机默认」。

**新增 `配置\账户.json`**

```json
{"格式版本": 2, "用户码": "u7k3m9qz4t2p", "昵称": "ajmn", "创建时间": "2026-10-08 23:40", "是否自定义": false}
```

**用户码规则（预留编码空间）**

| 前缀 | 含义 | 行为 |
| --- | --- | --- |
| `u` | 正式用户 | 正常计入统计 |
| **`t`** | **测试用户（预留）** | 默认**不计入统计**；设置里有「显示测试数据」+「一键清空测试数据」 |
| `s` | 保留（系统/内部） | 保留位，便于以后扩展 |

生成规则：时间戳 + 随机数 → Base32，去掉易混字符 `0/O/1/I`，固定 12 位、前缀 `u`。
首次打开弹一次「欢迎使用，用户 uXXXXXXXXXXXX」，可直接确定或改昵称；设置里以后能改。

**交换文件（导出/导入、手机端用）**：JSON，头部 `{格式版本, 用户码, 昵称, 设备, 导出时间, 条数}`；
导入时用表头用户码做「**是不是你自己导出的文件**」校验（防止自我导入造成重复），记录本体自带归属/来源。

### 9.4 安装包（单文件 setup.exe）与数据位置

- 安装包 = **一个 exe**：双击 → 中文向导 → 选择安装位置 → 解压安装 → 可选桌面/开始菜单快捷方式 → 可卸载。
- **「选择安装位置」页的路径框下方有一行提示**（照用户要求）：
  > 建议装在 D 盘或用户目录。若装在 `C:\Program Files`，Windows 不允许程序往自己目录写数据，
  > 账本会自动保存到「文档\记账本」（设置里可查看和更改）。
- **数据位置规则（重要）**：程序启动时判断「exe 所在目录是否可写」——
  可写就写在旁边（保持便携行为），不可写就退到 `%LOCALAPPDATA%\记账本\`（或「文档\记账本」）；
  `JIZHANG_ROOT` 环境变量仍然优先。设置页显示实际数据目录，可一键打开。
- 安装包内放**自包含版**（用户机器上不需要预装 .NET）；轻量版另出一个包（可选）。

### 9.5 v3.0 预留：安卓轻量录入端

- 独立代码（Kotlin + Jetpack Compose，APK 目标 5–15MB），只做「连续记多笔 / 改自己的 / 导出分享」；
  统计、图表、月报、导入策略全部留在电脑端。
- 通过 9.2 的交换文件互通；手机端不含编号分配逻辑（编号是电脑端内部主键）。
- 已知限制：安卓工具链很大（Android SDK 1GB+）；本机无法真机/模拟器验证，只能保证编译通过。
