## 3. 数据格式（格式版本 1，v0.2 仍能读）

- **位置**：默认程序所在目录；冻结版按 `sys.frozen` 判断是否 PyInstaller 打包后的环境（`paths.py`）。
- **结构**：`数据\年\月\YYYY-MM-DD.tsv`，每天一个文件，**TSV、7 列、不存日期列**（编号前 8 位 = 日期，文件名也带日期）。
- **编号**：`YYYYMMDD-NNN`。金额两位小数、必须 > 0。类型只认 支出 / 收入。
- **格式演进**（v0.2 侧实现）：1 = 7 列 TSV → 2 = 9 列 TSV（加「归属」「来源」）→ 3 = 每日 JSONL（一行一条、字段带名字，当前）。
- **单向兼容**：v0.1 **读不懂格式 3**；升级到格式 3 后不要再用 v0.1 打开账本。

## 4. 构建与运行

```powershell
python v0.1\记账.py          # 直接跑（需要本机有 Python + tkinter）
v0.1\打包exe.bat             # PyInstaller 打包，产出 LedgerBook\记账本.exe
python v0.1\selftest.py      # 自检
```

## 5. 约定与坑

1. `ledger\` 包**不许 import 任何界面库**（前端可以是 tkinter、命令行、或别的东西）——这是它被称为"契约"的原因。
2. `model.py` 里的列顺序、编号、金额/日期写法**改动即等于改数据格式**：必须同时升级 `DATA_FORMAT_VERSION`、
   写迁移逻辑（老文件仍要能读）、并先备份。
3. 早期打包用 `build.spec` 里的 `CONF` 自定义输出目录——PyInstaller 只会建它自己解析出来的默认路径，
   所以脚本里要**自己把目录建出来**（`build.spec` 里有注释说明）。
4. 项目的历史没有 git，v0.1 的源码就是这个文件夹本身；如需更早的状态只能靠 `历史版本\` 里的存档。

## 6. 与 v0.2 的接口

- **读**：v0.2 的 `LedgerBook.Core` 实现了 `model.py` 定义的格式 1/2/3 读取与升级。
- **写**：v0.2 默认写格式 3；导出 CSV（UTF-8 带 BOM）可给 Excel 或任何工具。
- **回退**：若必须回到 v0.1 可读的形态，用 v0.2 的导出 CSV / 或在 v0.2 里导出后手工整理成 TSV。
